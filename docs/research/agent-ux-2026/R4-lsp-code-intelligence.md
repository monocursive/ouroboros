### 1.1 OpenCode (most complete open-source reference)

- **Servers.** The docs list 31+ built-in definitions: astro, bash, clangd, csharp/razor, clojure-lsp, dart, deno, elixir-ls, eslint, fsharp, gleam, gopls, hls, jdtls, julials, kotlin-ls, lua-ls, nixd, ocaml-lsp, oxlint, intelephense, prisma, pyright, ruby-lsp, rust-analyzer, sourcekit-lsp, svelte, terraform, tinymist, typescript, vue, yaml-ls, zls ([docs](https://opencode.ai/docs/lsp/)). Servers activate by file extension; each definition has a root finder (`NearestRoot` walking up to markers such as package lockfiles, `go.mod`/`go.work`, `Cargo.toml`, `mix.exs`, `Gemfile`, `compile_commands.json`, `Package.swift`) and a spawn function that may auto-install into OpenCode's cache bin dir (gopls via `go install`, elixir-ls downloaded and compiled from GitHub, clangd/zls prebuilt binaries); downloads can be disabled with `OPENCODE_DISABLE_LSP_DOWNLOAD` ([server.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/lsp/server.ts), [DeepWiki](https://deepwiki.com/sst/opencode/5.4-language-server-integration)).
- **Feedback loop.** `edit.ts`: after a successful edit it calls `lsp.touchFile(filePath, "document")`, then `lsp.diagnostics()`, filters to the edited file, and appends `"LSP errors detected in this file, please fix:"` plus the block to `"Edit applied successfully."` No count cap in the code ([edit.ts](https://github.com/anomalyco/opencode/blob/dev/packages/opencode/src/tool/edit.ts)). Diagnostics are cached from `publishDiagnostics`, debounced 150 ms, deduped on code/severity/message/source/range; initialize timeout 45 s; document-diagnostics wait 5 s, workspace 10 s ([DeepWiki](https://deepwiki.com/anomalyco/opencode/2.8-lsp-and-code-formatting), secondary). Formatters (prettier, biome, ruff, gofmt, mix format, clang-format, ktlint, rubocop…) run after writes and then `touchFile` again.
- **Policy shift.** The current docs say "LSP is disabled by default" and, verbatim: "Language servers can get out of sync, use significant memory, vary by version or project, and slow down agent workflows. In many projects it is better to have the agent run lint, typecheck, or other diagnostic CLI tools directly, so errors are fed back into the agent loop without those tradeoffs." They recommend documenting those commands in `AGENTS.md` ([docs](https://opencode.ai/docs/lsp/)). Two issues illuminate why: agents treated appended diagnostics as failed edits and looped ([#9102](https://github.com/anomalyco/opencode/issues/9102), closed), and a request to add a `diagnostics` operation to the `lsp` tool and auto-surface diagnostics on `read` was closed as not planned ([#16569](https://github.com/anomalyco/opencode/issues/16569)). A 2026 taxonomy paper still describes OpenCode's LSP as "experimental LSP integration for symbol navigation" ([arXiv 2604.03515](https://arxiv.org/html/2604.03515)).
- **Daemon shape.** `opencode serve` is a headless HTTP server (OpenAPI, default port 4096) to which the TUI, web and IDE clients attach; LSP servers live server-side with a `/lsp` status endpoint ([server docs](https://opencode.ai/docs/server/)).

### 1.2 Claude Code

- **Configuration surface.** Plugins declare `lspServers` with `command`, `extensionToLanguage` (required) and optional `args`, `transport` (socket accepted but "runs every server over stdio"), `env`, `initializationOptions`, `settings` (sent via `workspace/didChangeConfiguration`), `workspaceFolder`, `startupTimeout`, `shutdownTimeout`, `restartOnCrash` (default true), `maxRestarts`, and `diagnostics` (default true; set false "to keep code navigation but suppress automatic diagnostic injection") ([plugins-reference](https://code.claude.com/docs/en/plugins-reference)).
- **What the model gets.** Official docs: "Automatic diagnostics: after every file edit Claude makes, the language server reports errors and warnings back… If Claude introduces an error, it notices and fixes it in the same turn" and "Code navigation: jump to definitions, find references, get type info on hover, list symbols, find implementations, and trace call hierarchies" ([discover-plugins](https://code.claude.com/docs/en/discover-plugins)). The nine operations (goToDefinition, findReferences, hover, documentSymbol, workspaceSymbol, goToImplementation, prepareCallHierarchy, incomingCalls, outgoingCalls) are enumerated in the community marketplaces ([boostvolt](https://github.com/boostvolt/claude-code-lsps/blob/main/README.md), [Piebald](https://github.com/Piebald-AI/claude-code-lsps)).
- **Official plugins (11):** clangd, csharp-ls, gopls, jdtls, kotlin-language-server, lua-language-server, intelephense, pyright-langserver, rust-analyzer, sourcekit-lsp, typescript-language-server; binaries are not bundled, and "Claude may prompt you to install the corresponding plugin" when a server is already on PATH ([discover-plugins](https://code.claude.com/docs/en/discover-plugins); [marketplace.json](https://raw.githubusercontent.com/anthropics/claude-plugins-official/main/.claude-plugin/marketplace.json) also lists `liquid-lsp`). Community marketplaces add Elixir (elixir-ls), Ruby (Solargraph), Gleam, Zig, etc.; Piebald notes Julia and ElixirLS "significant startup times during initial project compilation" and that LSP landed in **v2.0.74** (secondary; I could not fetch that changelog section directly).
- **Changelog trail (primary where fetched):** v2.1.107 "Fixed stale pre-edit LSP diagnostics appearing after an edit and causing Claude to re-read files it just edited"; v2.1.84 `clientInfo` sent in `initialize`; v2.1.216 "Fixed multi-second UI stalls after editing a file with thousands of IDE diagnostics while the IDE extension is connected"; v2.1.234 "Fixed whole-prompt-cache invalidation when a language server disconnected or reconnected mid-session" ([changelog](https://code.claude.com/docs/en/changelog); v2.1.107/84 via [claudefa.st mirror](https://claudefa.st/blog/guide/changelog), secondary).
- **Documented caveats:** "language servers like rust-analyzer and pyright can consume significant memory on large projects… disable the plugin… and rely on Claude's built-in search tools instead"; "False positive diagnostics in monorepos" for unresolved internal imports ([discover-plugins](https://code.claude.com/docs/en/discover-plugins)).
- **IDE path.** The VS Code extension hosts a local MCP server; only two tools reach the model, including `mcp__ide__getDiagnostics`, which "Returns language-server diagnostics — the errors and warnings in VS Code's Problems panel. Optionally scoped to one file." The CLI in the integrated terminal "automatically integrates with your IDE for features like diff viewing and diagnostic sharing" ([vs-code docs](https://code.claude.com/docs/en/vs-code)).
- **Hooks as the universal loop.** `PostToolUse` with matcher `Edit|Write`: exit 2 "Shows stderr to Claude; the tool already ran"; JSON `hookSpecificOutput.additionalContext` injects text ([hooks](https://code.claude.com/docs/en/hooks)).
- **Retrieval stance.** Boris Cherny: "Early versions of Claude Code used RAG + a local vector db, but we found pretty quickly that agentic search generally works better. It is also simpler and doesn't have the same issues around security, privacy, staleness, and reliability" ([X post](https://x.com/bcherny/status/2017824286489383315)).

### 1.3 Codex CLI, Gemini CLI, Amp

- **Codex:** as of v0.125.0 "Codex CLI has no built-in LSP support"; [#8745](https://github.com/openai/codex/issues/8745) (open) proposes `codex --lsp=auto|on|off`, `codex lsp status|diagnostics`, 25+ curated server mappings, a managed pinned-version cache, `publishDiagnostics` as mandatory feedback with navigation optional; [#14799](https://github.com/openai/codex/issues/14799) pushes project-scoped MCP as the near-term path ([status article](https://codex.danielvaughan.com/2026/04/25/codex-cli-lsp-integration-language-server-semantic-code-intelligence/)). The [codex-lsp](https://github.com/code-yeongyu/codex-lsp) plugin is a good reference design: a `PostToolUse` hook extracts files touched by `apply_patch`/`write`/`edit`, checks them, and "returns Codex PostToolUse blocking feedback and injects the same diagnostics as additional context"; it exposes `lsp.status`, `lsp.diagnostics`, `lsp.goto_definition`, `lsp.find_references`, `lsp.symbols`, `lsp.prepare_rename`, `lsp.rename`; "Deletes are ignored because they cannot introduce new diagnostics."
- **Gemini CLI:** [#6690](https://github.com/google-gemini/gemini-cli/issues/6690) closed as duplicate (internal roadmap); [PR #15149](https://github.com/google-gemini/gemini-cli/pull/15149) (Dec 2025, p1, TS/JS MVP via typescript-language-server) appended diagnostics inside `<lsp_diagnostics>` tags, with `WriteFile` showing all severities and `Edit` only ERROR, and was closed unmerged on 2026-01-15. The docs index has no LSP/diagnostics entry today. The IDE companion shares 10 recent files, cursor, selection (16 KB) and native diff, not diagnostics ([ide-integration](https://geminicli.com/docs/ide-integration/)).
- **Amp:** a `get_diagnostics` tool exists; in Neovim a companion "registers a `get_diagnostics` tool in Amp and pulls diagnostics from the running Neovim instance" over amp.nvim's local WebSocket ([amp.nvim](https://github.com/ampcode/amp.nvim)). Whether the standalone CLI spawns language servers itself is **unverified**. Sourcegraph's MCP server exposes "search, code nav, Deep Search, file browsing, commit/diff search", with optional SCIP "compiler-accurate precision" per repository ([context-compare](https://sourcegraph.com/resources/context-compare)); Cody Free/Pro were sunset 2025-07-23 in favour of Amp ([announcement](https://sourcegraph.com/blog/changes-to-cody-free-pro-and-enterprise-starter-plans)).

### 1.4 Serena and other LSP-MCP bridges

- **Serena** (28.4k stars): symbol tools `find_symbol`, `find_referencing_symbols`, `find_declaration`, `find_implementations`, `get_symbols_overview`, `get_diagnostics_for_file`, `insert_after_symbol`/`insert_before_symbol`, `replace_symbol_body`, `rename_symbol`, `safe_delete_symbol`, `restart_language_server`; file/pattern tools; memories; JetBrains-only move/inline/inspections/debug ([tools](https://oraios.github.io/serena/01-about/035_tools.html)). Languages: Python (pyright default; basedpyright, ty, pyrefly, jedi), TS, Go, Rust, Java, Kotlin (official LS, "pre-alpha"), C/C++ (clangd, `compile_commands.json` recommended), Ruby (ruby-lsp default or Solargraph), **Elixir via Expert with auto-download**, Erlang "experimental, might be slow or hang" ([languages](https://oraios.github.io/serena/01-about/020_programming-languages.html)). `serena project index` "pre-caches symbol information provided by the language server(s)" to "avoid delays during the first tool invocation" ([workflow](https://oraios.github.io/serena/02-usage/040_workflow.html)). Config exposes per-server timeouts (TypeScript `indexing_timeout` 30 s, `server_ready_timeout` 10 s; Scala 180 s; Svelte 120 s) and JVM heaps (`jdtls_xmx` 3G; Kotlin `-Xmx2G`) ([configuration](https://oraios.github.io/serena/02-usage/050_configuration.html)). Known failures: ~30 GB memory on C#/C++/Rust projects ([#944](https://github.com/oraios/serena/issues/944)); Roslyn load timeouts ([#513](https://github.com/oraios/serena/issues/513), [#537](https://github.com/oraios/serena/issues/537)).
- **isaacphi/mcp-language-server** (Go, ~1.5k stars): definition, references, diagnostics, hover, rename, edit-file; one `--workspace` and one `--lsp` per process ([repo](https://github.com/isaacphi/mcp-language-server)).
- **lsp-client / LSAP**: wraps raw LSP into "agent-native" composed requests addressed by symbol path (e.g. `"locate": "User.validate"`) returning Markdown reports, with a two-step safe rename; no published evaluation ([LSAP](https://github.com/lsp-client/LSAP), [ecosystem](https://lsp-client.github.io/)).
- **ast-grep MCP**: `ast_search`, `ast_replace` (dry-run), `ast_run_rule` (YAML rules), `ast_explain_pattern` ([repo](https://github.com/ast-grep/ast-grep-mcp)).
- **Augment Context Engine MCP**: single `codebase-retrieval` tool; local index via Auggie CLI or remote GitHub-app index; supports Claude Code, Cursor, Codex, Gemini CLI, Zed, Kiro, OpenCode…; "$0.03–$0.06 per query" ([MCP docs](https://docs.augmentcode.com/context-services/mcp/overview)). Marketing page claims vs Claude Code on Terminal Bench 2.0 with Opus 4.7: 33% lower spend, 32% fewer tokens, +1.9 pp pass rate ([context-engine](https://www.augmentcode.com/context-engine), vendor-reported).
- **Greptile**: graph built by scanning files for functions/classes/variables, mapping calls/imports/usages, stored for query-time traversal ([docs](https://www.greptile.com/docs/how-greptile-works/graph-based-codebase-context)); the oft-repeated "tree-sitter + per-node docstrings + embeddings" description is **unverified** against Greptile's docs.

### 1.5 tree-sitter approaches

- **Aider repo map:** `*-tags.scm` queries extract `name.definition.*`/`name.reference.*` tags; graph nodes are files, edges are shared identifiers with weights boosted for chat files, user-mentioned identifiers and path components; PageRank with a personalization vector; binary search over inclusion thresholds to fit `--map-tokens` (default 1k, ×8 when no files are in chat); disk tag cache keyed on mtime ([repomap](https://aider.chat/docs/repomap.html), [2023 post](https://aider.chat/2023/10/22/repomap.html), [DeepWiki](https://deepwiki.com/Aider-AI/aider/4-repository-understanding-and-context)). Aider publishes no benchmark isolating the map.
- **Cline/Roo `list_code_definition_names`:** top-level directory only, `slice(0, 50)` files, 17 extensions, captures filtered by `name.includes("name")`, output delimited with `|----` ([source](https://github.com/cline/cline/blob/8fbccff8538cde243ceb08d644a15dbf2256b544/src/services/tree-sitter/index.ts)); reliability complaints about C#/TSX and WASM loading ([#4366](https://github.com/cline/cline/issues/4366)).
- **Kiro CLI:** tree-sitter "works out-of-the-box for 18 languages with symbol search, document outlines, and AST-based pattern matching/rewriting"; LSP is the optional second layer ([docs](https://kiro.dev/docs/tools/code-intelligence/)).

## 2. The feedback loop after edits

| System | Trigger | Scope | Severity | Freshness/wait | Noise bound | Wording |
|---|---|---|---|---|---|---|
| OpenCode | every edit/write | edited file only | errors (label) | touchFile → wait ≤5 s doc diag; 150 ms debounce | dedupe; no count cap | "Edit applied successfully." + "LSP errors detected in this file, please fix:" |
| Claude Code | every edit | files with *new* diagnostics ("Found 3 new diagnostic issues in 2 files") | errors + warnings | stale pre-edit diagnostics fixed in v2.1.107 | per-server `diagnostics:false`; UI stall fix for thousands of IDE diagnostics | injected into context; Ctrl+O to view |
| Hermes | `write_file`/`patch` | edited file | n/a | baseline captured before write; re-query; "freshness-gated"; `wait_timeout` 5 s else "no LSP data" | only *new* diagnostics; silent fallback on LSP failure | appended to tool result |
| Gemini PR #15149 (unmerged) | WriteFile/Edit | edited file | WriteFile all; Edit ERROR only | init timeout | severity | `<lsp_diagnostics>` tags |
| codex-lsp | `PostToolUse` hook | files touched by the edit | errors | n/a | deletes ignored | blocking feedback + additionalContext |
| Kilo Code | every edit | edited file | n/a | default TS path shells `tsgo --noEmit` | n/a | in tool result |
| Cline / Copilot agent mode | continuous | editor Problems | lint + compile | editor-driven | n/a | "get compile or lint errors from the editor" ([VS Code blog](https://code.visualstudio.com/blogs/2025/02/24/introducing-copilot-agent-mode)) |
| Kiro IDE 0.x | automatic on file open/edit | extension diagnostics | lint + syntax + type | "under 35ms" | n/a | tool output |
| Aider | after every edit | lint + tests | lint/test output | synchronous | `max_reflections` cap | re-prompt with errors |
| Claude Code hooks / OpenCode AGENTS.md | `Edit|Write` hook / model-run CLI | whatever the command checks | as configured | synchronous | your script | exit 2 stderr / tool output |

**Evidence of effect**

- SWE-Master (Renmin Univ. + BOSS Zhipin, Feb 2026): adding an `lsp_tool` (13 ops: go_to_definition/declaration/type_definition/implementation, call hierarchy, signature_help, document_symbols, document_color, workspace_symbols, find_references; pyright in Docker) to an OpenHands-style scaffold on SWE-bench Verified: MiniMax-M2.1 68.4% → 70.4% resolve and 82.0 → 77.0 turns; GLM-4.7 66.2% → 67.6%, 97.3 → 94.4 turns ([arXiv 2602.03411](https://arxiv.org/html/2602.03411)). Modest, consistent, and mostly a *turn-count* win.
- "Code Isn't Memory" (June 2026): a hybrid structural index (vector + tree-sitter call graph + BM25, Merkle-incremental) exposed as `codebase_search` and `codebase_graph` inside a fixed harness with Opus 4.7 on 91 SWE-PolyBench Verified/SWE-bench Pro tasks: resolve 50.4% (index on) vs 41.9% (off) vs 45.3% (OpenCode, ripgrep); localization acc@5 84.5% vs 44.3% vs 75.3%; $/solve $2.30 vs $2.84 vs $2.92; turns 28.3 vs 36.2 vs 36.0; largest gains on 3+-file changes (91.3% vs 44.9% acc@5). Their framing: the question is "whether the workload includes multi-file changes where structural ranking pays off" ([arXiv 2606.22417](https://arxiv.org/html/2606.22417)).
- Kiro: direct diagnostics access produced a "29% reduction in command executions" (fewer build/test runs) ([blog](https://kiro.dev/blog/empowering-kiro-with-ide-diagnostics/), vendor-reported).
- CircleCI (June 2026) on Vue core (~149K LOC): Claude Code with LSP cut output tokens 31% (Opus) / 33% (Sonnet), and "the LSP was the only configuration that never missed" ([CircleCI](https://circleci.com/blog/claude-code-lsp/); small informal test).
- Cursor (Nov 2025): semantic search on top of grep gave "12.5% higher accuracy in answering questions (6.5%–23.5% depending on the model)", +0.3% code retention (+2.6% on 1,000+ file repos), and 2.2% fewer dissatisfied follow-ups in A/B; embedding model trained from agent traces; "the combination of these two [grep + semantic] leads to the best outcomes" ([semsearch](https://cursor.com/blog/semsearch)).
- Serena's own evaluation (self-judged by the agent; Opus 4.6 on Tianshou, 26K LOC Python, April 2026): cross-file rename 1 call vs 9, symbol move 1 vs 8–12; but for 1–3-line edits the native `Edit` sends ~120 chars vs Serena ~550, and "roughly 40–60% of a typical coding session" is out of Serena's scope ([results](https://oraios.github.io/serena/04-evaluation/030_results/010_cc_on_tianshou.html)).
- Negative/neutral evidence: a ManoMano benchmark on a 36K-LOC Java service reportedly found Serena "cost nearly four times as much and took 60% longer" for a simple find-a-rule task, and found Claude Code's built-in LSP "hallucinating methods and missing test classes" (search snippet of [the article](https://medium.com/manomano-tech/project-aegis-benchmarking-ai-agents-and-why-serena-is-our-new-must-have-311673db35dd); article blocked to fetch — **partially verified**). OpenCode's maintainers turned LSP off by default and recommended CLI typecheck/lint instead (section 1.1). Anthropic's docs tell users to disable LSP plugins on memory pressure (section 1.2).

**How noise is bounded in practice:** (1) edited-file scope (OpenCode, Hermes, Gemini PR); (2) *new-only* via pre-edit baseline (Hermes) or "new diagnostic issues" accounting (Claude Code); (3) severity gates (Gemini PR: Edit errors-only); (4) version/freshness gating so stale pre-edit diagnostics are never shown (Hermes explicit; Claude v2.1.107 fix); (5) bounded waits with silent fallback (Hermes 5 s → "no LSP data"; OpenCode 5 s/10 s); (6) dedupe (OpenCode); (7) explicit success wording so the model does not retry (OpenCode #9102); (8) per-server opt-out (Claude `diagnostics:false`); (9) a files cap was proposed but not adopted in Hermes (`MAX_PROJECT_DIAGNOSTICS_FILES=5`, [issue #516](https://github.com/NousResearch/hermes-agent/issues/516)).

## 3. Which operations to expose as tools vs. run silently

| Operation | Exposed by | Evidence | Recommendation |
|---|---|---|---|
| goToDefinition / findReferences / hover / documentSymbol / workspaceSymbol / implementation / call hierarchy | OpenCode, Claude Code, Kilo (exp.), Kiro CLI, Serena, SWE-Master, mcp-language-server, codex-lsp | SWE-Master +1.4–2.0 pp, −3–5 turns; Serena 1 vs 9 calls for cross-file ops; CircleCI "never missed" | Expose as one `code_intel` tool with an `operation` enum (the 9-op set is now a de-facto standard across OpenCode, Claude Code, Kilo). References and call hierarchy are the highest-value ops; hover mainly saves file reads. |
| diagnostics (on demand, per file/project) | Zed, Amp, Kiro, Serena, mcp-language-server, codex-lsp | Zed's doc: "useful after making edits to determine if further changes are needed"; OpenCode declined (#16569) | Expose **and** auto-inject. Auto-inject covers the edited file; the tool covers "what is broken project-wide" without spawning a compiler. |
| rename (workspace edit) | Serena, Kiro CLI, mcp-language-server, codex-lsp, LSAP (two-step) | Serena eval: rename collapses 9 steps into 1 atomic call | Expose with preview-then-apply; it is the one refactor where LSP beats text editing decisively. |
| symbol-addressed edits (insert_after_symbol, replace_symbol_body) | Serena, LSAP | Serena: better for ≥19-line rewrites, worse for 1–3-line edits (4.5× payload) | Optional. Keep line/anchor edits as default; symbol edits for whole-body replacement. |
| code actions / organize imports / format | OpenCode runs formatters silently; nobody exposes code actions | no evaluation found | Run silently (format-on-write, then re-touch the file). Do not expose code actions; quick-fixes are noisy and server-specific. |
| semantic search / embeddings | Cursor, Augment, "Code Isn't Memory", Moatless (only OSS agent with FAISS, per [taxonomy](https://arxiv.org/html/2604.03515)) | Cursor +12.5%; structural hybrid +7.9 pp resolve; Anthropic dropped RAG for agentic search | Not in the minimal set. Worth it for large repos and multi-file tasks if the index is incremental, local and structural (graph+BM25+vector), not a bare vector store. |
| repo map / outline | Aider (passive), Kiro tree-sitter, Cline | no isolated benchmark; 8 of 13 OSS agents use plain grep | Cheap; provide a tree-sitter outline tool (`documentSymbol` fallback when no LSP) and optionally a PageRank map for orientation. |
| import resolution / type checking | Kilo `tsgo --noEmit`, hooks | OpenCode: CLI tools are "better" in many projects | Silent: project typecheck via CLI hook, bounded to changed files when the toolchain allows. |

## 4. Mechanics

- **Language detection.** All clients key on file extension (`extensionToLanguage` in Claude Code; `extensions` in OpenCode), then pick a project root by nearest marker file (OpenCode `NearestRoot`/`StrictNearestRoot`; Gemini PR's root walk had an off-by-one bug at filesystem root — a reviewer caught it). Claude Code adds an explicit `workspaceFolder`.
- **Discovery/install.** Three stances: (a) never install, prompt the user (Claude Code official plugins, Kiro CLI: "not auto-installed"); (b) install into a private cache with pinned versions (OpenCode `Global.Path.bin`; Hermes `<HERMES_HOME>/lsp/bin/`, "Nothing is ever installed to /usr/local/"; Codex proposal); (c) auto-download with checksum (Serena for several servers, SHA-256). Prefer the user's toolchain binary when present (OpenCode resolves the local `node_modules` tsserver; pyright/ty detect venvs).
- **Lifecycle.** Lazy spawn on first touch of a matching file (OpenCode, Hermes, Kiro background processes); initialize timeouts of 45 s (OpenCode, Kilo) or configurable `startupTimeout` (Claude); restart-on-crash with a cap (Claude `restartOnCrash`/`maxRestarts`); a "broken" set so a failing server is not respawned every edit (OpenCode); idle shutdown (Hermes `idle_timeout` 600 s); `shutdownTimeout` then kill (Claude). Claude Code sends `clientInfo` (v2.1.84) — do the same; some servers key behaviour on client identity.
- **Document sync.** `didOpen`/`didChange` with version tracking (OpenCode), re-touch after formatting; diagnostics are only trusted when their version matches the current content (Hermes; Claude's v2.1.107 fix exists because stale pushes leaked).
- **Startup latency.** Worst offenders on record: ElixirLS and Julia (initial compile; Piebald), jdtls (Serena ships 3 GB heap defaults), Metals/Scala (180 s indexing timeout), Roslyn (10 s hard-coded timeout broke .NET loads, Serena #513), tsserver on large projects (first `find_references` could race project load, per Serena changelog notes). Serena's answer is pre-indexing (`serena project index`); Kiro's is per-workspace `/code init`.
- **Multi-root / monorepos.** Per-file root selection (OpenCode) handles multiple packages but yields one server per root, so memory multiplies; Anthropic warns of false-positive unresolved-import diagnostics in monorepos; Zed's remote mode notes performance problems above 100k files ([remote-development](https://zed.dev/docs/remote-development)).
- **Daemon-style ownership (precedents).** OpenCode keeps LSP servers in the long-lived `serve` process shared by TUI/web/IDE clients; Zed runs "the source code, language servers, tasks, and the terminal" on the remote machine while UI and tree-sitter stay local; Claude Code spawns servers per CLI process and invalidates the whole prompt cache when one disconnects (v2.1.234) — a cost a shared daemon avoids.

## 7. Beyond LSP

- **Structural search:** ast-grep MCP gives pattern search/replace with dry-run and YAML rules; Kiro CLI bundles AST pattern matching/rewriting. No benchmark found; value is deterministic multi-site rewrites.
- **Indexes and context engines:** Cursor (Merkle-tree sync, AST-boundary chunking, encrypted paths, embeddings retrieved then chunks decrypted client-side; indexing "several orders of magnitude faster" for near-identical team copies), Augment (MCP `codebase-retrieval`, local or remote index, per-query pricing), Greptile (relationship graph + agentic multi-hop in v3), Sourcegraph (exhaustive cross-repo search, optional SCIP precision, MCP for agents). The academic hybrid in "Code Isn't Memory" is the most transparent: vector + tree-sitter graph + BM25 with incremental Merkle updates, and the gains concentrate in multi-file tasks.
- **What open-source agents do at monorepo scale:** mostly nothing beyond ripgrep (8 of 13 scaffolds in the [taxonomy](https://arxiv.org/html/2604.03515)); Aider's PageRank map; Prometheus's Neo4j graph (11 tools) and Moatless's FAISS are research systems. Anthropic's public position is that agentic grep "beat everything" once models got good, with fewer staleness/privacy problems. The practical cost side: Augment's $0.03–0.06/query, Cursor's cloud index, Serena's 30 GB incidents.

## Synthesis

### (a) Minimal integration that captures most of the value

1. **Post-edit diagnostics, bounded.** After each edit/write: touch the file, wait ≤5 s for a diagnostics push whose version matches the new content, diff against the pre-edit baseline, and append only *new* errors (warnings optional) for that file, with explicit "edit applied" wording and a hard cap (e.g. 20 items, then "+N more"). On timeout or server failure, say "no LSP data" and move on. Every element is taken from a shipped design: OpenCode (scope, wording after #9102), Hermes (baseline diff, freshness gate, silent fallback), Claude Code (new-only accounting, stale fix), Gemini PR (severity gate). Evidence it matters: Kiro −29% command executions; CircleCI never-missed; Copilot/Cline/Aider all converge on edit → errors → fix loops.
2. **A CLI typecheck/lint hook as the universal fallback**, declared per project (AGENTS.md / hook config) and run on changed files after edits — this is what OpenCode now recommends over LSP and what Kilo does by default for TS (`tsgo --noEmit`). It covers languages without a good server and catches cross-file breakage the per-file diagnostics miss.
3. **One navigation tool** with the 9-op enum (definition, references, hover, documentSymbol, workspaceSymbol, implementation, call hierarchy ×3), addressed by `file:line:character`, lazily spawning the server. SWE-Master shows this is worth ~1–2 pp and 4–6% fewer turns on Python; Serena shows order-of-magnitude call reductions for reference/rename tasks. Fall back to a tree-sitter outline when no server exists.

### (b) The full, differentiating integration

- Add `diagnostics` (file/project) and `rename` (preview → apply) operations; symbol-addressed edits for whole-body rewrites; format-on-write and re-touch; a tree-sitter repo outline for orientation.
- A local, incremental **structural index** (tree-sitter call graph + BM25, optional embeddings) exposed as `codebase_search`/`codebase_graph` for multi-file tasks — the only retrieval addition with a controlled ablation showing a resolve gain (+7.9 pp) at lower $/solve.
- An **IDE bridge** so editor diagnostics (VS Code/Neovim/Zed) feed the same pipeline when an editor is attached (Claude's `ide` MCP, amp.nvim pattern), and an ACP/MCP-style way to publish the runtime's diagnostics back to editors, since ACP itself has no diagnostics channel.
- UI: per-file diagnostic badges in the transcript, expandable detail, `@symbol`/`@diagnostics` mentions, and jump-to-definition affordances on file:line references.

### (c) Recommended architecture for a daemon-style multi-session runtime

- **Ownership:** the long-lived runtime owns an **LSP pool**, not the session. Key = (host, workspace root, server id). Sessions acquire a handle; the pool ref-counts, spawns lazily on first touch, sends `clientInfo`, and shuts down idle servers (Hermes' 600 s is a reasonable default). Servers must run **where the files are** (Zed remote model; OpenCode server-side), so a multi-machine runtime needs one pool per host with the session routing requests to the host that owns the workspace.
- **Crash policy:** restart with backoff up to `maxRestarts`, then mark the (workspace, server) broken for the session's lifetime and fall back to CLI diagnostics; surface state on a `/lsp` status endpoint and in the UI. Never let an LSP failure fail a write.
- **Document sync across sessions:** serialize `didChange` per document through the pool with a monotonically increasing version; record which session produced each version so diagnostics can be attributed and injected into the right transcript; gate every diagnostics read on version equality.
- **Tool exposure:** one `code_intel` tool with an operation enum, plus diagnostics on demand; rename gated by approval like other workspace-wide mutations. Hide formatting and code actions behind the write path.
- **Diagnostics feedback policy (defaults):** edited-file scope, new-only, errors always/warnings configurable, cap + truncation, freshness-gated with 5 s budget, explicit success wording, per-server opt-out, and a project-level switch to prefer CLI typecheck when servers are known to be noisy (monorepos).
- **UI:** emit `diagnostics.changed {file, counts, version}` events from the pool; the TUI shows a compact badge and an expandable list; IDE clients map the same events onto editor decorations.
- **Memory governance:** per-server RSS watchdog with a soft limit, restart-on-breach, and a per-host budget that stops spawning new servers (the documented failure modes are 30 GB Serena processes and rust-analyzer/pyright on large repos).

### (d) Pitfalls, with evidence

- **Startup time and cold indexing:** 45 s initialize timeouts (OpenCode, Kilo); ElixirLS/Julia compile on first launch; Metals 180 s; Roslyn hard 10 s timeout; Serena's pre-index workaround. Spawn lazily and show status rather than block.
- **Noisy or misread diagnostics:** agents retried or abandoned edits when diagnostics were appended without a success line (OpenCode #9102); stale pre-edit diagnostics made Claude re-read files (v2.1.107); thousands of IDE diagnostics stalled the UI (v2.1.216); monorepo false positives (Anthropic docs); pre-existing errors drown new ones unless baseline-diffed (Hermes).
- **Server crashes and reconnects:** Claude Code's disconnect/reconnect invalidated the prompt cache (v2.1.234); Gemini's PR had an uncleared timer causing unhandled rejections. Keep the LSP client out of the model's prompt-cached context and isolate server death from the session.
- **Memory:** Serena #944 (~30 GB, C#/C++/Rust); Anthropic's explicit advice to disable plugins; JVM heaps of 2–3 GB per server by default. Budget per host, not per session.
- **Over-use for trivial tasks:** Serena's own numbers (small edits 4.5× more payload; 40–60% of a session out of scope) and the ManoMano report (4× cost for a simple lookup) argue for prompting the model to use grep/read for simple questions and code-intel for references, renames and multi-file work.
- **Staleness after branch switches and out-of-sync servers** (CircleCI caveat; OpenCode's stated tradeoff): restart servers on large tree changes and prefer the user's toolchain versions.
- **Ecosystem reality check:** two of the three largest vendor CLIs (Codex, Gemini) still ship nothing; OpenCode turned its integration off by default. The minimal set in (a) is cheap precisely because it degrades to CLI tools and never blocks a write.
