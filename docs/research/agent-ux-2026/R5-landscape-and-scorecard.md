# R5 — Coding-agent landscape and "top-5" scorecard (as of 2026-08-22)

Research lens: what makes the top coding agents top in mid-2026, what "top 5" actually means, and where a new entrant (an always-on, multi-machine agent daemon) can set the bar rather than chase it.

Method note. Every load-bearing number was re-checked on 2026-08-22 against a primary page (official leaderboard, vendor doc/pricing page, the original survey post) or pulled directly from `api.github.com` / `api.npmjs.org`. Claims without a primary source are tagged **unverified**. Systemic caveat: the Stack Overflow 2026 survey has **not published results** — it opened on 2026-06-23 ([SO blog](https://stackoverflow.blog/2026/06/23/the-2026-developer-survey-is-now-open-for-human-developers-only/)) and `survey.stackoverflow.co` still lists 2025 as latest. Widely shared "SO 2026" articles (e.g. [byteiota](https://byteiota.com/stack-overflow-dev-survey-2026-ai-at-84-trust-at-3/)) recycle the [2025 AI section](https://survey.stackoverflow.co/2025/ai) under a 2026 headline.

## 1. The landscape, ranked

### 1.1 What "top 5" means in August 2026

Three independent lenses produce a stable top tier:

| Lens | Source | Ranking it implies |
|---|---|---|
| Professional adoption (15k+ devs, May–Jul 2026) | [JetBrains, Aug 2026](https://blog.jetbrains.com/research/2026/08/ai-coding-agent-adoption-2026/) | Claude Code 39% (47% US; 31% use it as primary) > Copilot 21% (down from 29%) > Codex 16% (up from 3%) > Cursor 12% (down from 18%) > JetBrains AI 9% > OpenCode 7% > Antigravity 6% |
| Practitioner survey (906 respondents, Jan–Feb 2026) | [Pragmatic Engineer, Mar 2026](https://newsletter.pragmaticengineer.com/p/ai-tooling-2026) | Claude Code #1 ("zero to #1 in eight months"; 71% of agent users), Copilot 46%, Cursor 39%, Codex already at ~60% of Cursor's usage, Gemini CLI / OpenCode / Antigravity ~10% each. "Love" rating: Claude Code 46%, Cursor 19%, Copilot 9% |
| Agent benchmark (harness + model) | [Terminal-Bench 2.1](https://www.tbench.ai/leaderboard/terminal-bench/2.1) | Claude Code + Fable 5 83.8% (Jun 7) > Codex + GPT-5.5 83.1% (May 1) > Terminus 2 + Fable 5 80.4% > Cursor CLI + Grok 4.5 79.3% (Jul 9) > Claude Code + Opus 4.8 78.9% |
| Editorial power ranking (weights: 30% technical, 25% usability, 25% value, 20% accessibility) | [LogRocket, Aug 2026](https://blog.logrocket.com/ai-dev-tool-power-rankings/) | OpenCode #1, Claude Code #2, Cursor #3, Windsurf/Devin Desktop #4, Grok CLI #5 |

Synthesis: **the consensus top five is Claude Code, OpenAI Codex, Cursor, GitHub Copilot, OpenCode**, with Google's Antigravity (Gemini CLI's successor) sixth and Devin, Factory Droid, Amp and Pi as contenders. Seats are earned three ways: (a) harness quality on a frontier model (Claude Code, Codex), (b) installed base and procurement (Copilot, Cursor), (c) open-source/model-agnostic freedom (OpenCode, Pi). An entrant needs a credible answer on one axis and a non-embarrassing one on the other two. The 2026 framing is explicit: "The model race ended in a tie at the top. What separates these eight agents is the harness, the surfaces, and the token bill" ([firecrawl.dev](https://www.firecrawl.dev/blog/best-ai-coding-agents)); Thoughtworks' April Radar rates "team of coding agents" *Assess* and calls subagents "table stakes" ([Thoughtworks](https://www.thoughtworks.com/radar/techniques/team-of-coding-agents)).

## 3. Developer-sentiment themes: what separates a great agent in 2026

1. **Harness over model.** Frontier models converged; developers pick on loop behaviour, surfaces and token bill ([firecrawl](https://www.firecrawl.dev/blog/best-ai-coding-agents)). On Terminal-Bench 2.1 the same model (Fable 5) scores 83.8% in Claude Code vs 80.4% in the reference Terminus 2 harness — the harness is worth ~3 points.
2. **Verification is the bottleneck, not generation** ([Osmani](https://addyosmani.com/blog/code-agent-orchestra/); recurring HN theme per [Developers Digest](https://www.developersdigest.tech/blog/what-hacker-news-gets-right-about-ai-coding-agents-2026)). Anthropic's Opus 5 pitch is "agentic persistence: it verifies its own work and iterates" ([VentureBeat](https://venturebeat.com/orchestration/anthropic-launches-claude-opus-5-a-cheaper-ai-model-for-coding-agents-and-enterprise-workflows)); `/deep-research` filters claims that fail adversarial cross-checking ([workflows doc](https://code.claude.com/docs/en/workflows)). Agents that show evidence win.
3. **Token efficiency and cost control are features.** Community reports put Claude Code at 3–4x Codex's token use; one HN user burned ~$1,850 API-equivalent in 30 days on a $100 Max plan ([firecrawl](https://www.firecrawl.dev/blog/best-ai-coding-agents)). Pragmatic Engineer's top two concerns are cost and usage limits. Lazy tool loading (Claude Code cut MCP bloat 46.9%) is expected.
4. **Honesty about limits and outages.** HN's Codex rate-limit thread concluded users value "transparent communication" as much as the fix ([HN](https://news.ycombinator.com/item?id=48247607)); Anthropic's UI-only explanation for #42796 met skepticism; Google's silent quota cut burned goodwill.
5. **Permission fatigue is being solved by classifiers.** Anthropic's 1,053-tester study: humans caught 13.6% of dangerous commands vs 89% for the auto-mode classifier, with human accuracy decaying after ~50 prompts ([9to5mac](https://9to5mac.com/2026/08/14/psa-claude-code-enabling-auto-mode-as-default-next-week-anthropic-says/), [auto-mode post](https://claude.com/blog/auto-mode)). Auto mode became the Pro/Max/Team default on Aug 14 with classifier tokens free. The bar is "no prompts, still safe", backed by OS sandboxing and worktree isolation.
6. **Orchestration beats autonomy.** "Multiple bounded agents with human checkpoints outperform single autonomous agents" (HN theme); Osmani's "3–5 teammates is the sweet spot"; Thoughtworks separates deliberate small teams from swarms.
7. **Terminal-first + IDE-for-review is the standard workflow** (Pragmatic Engineer); staff+ engineers are the heaviest agent users (63.5%).
8. **"It just works" onboarding and subscription bundles.** The $200 top tier converged across Anthropic, OpenAI and Cursor ([tech-insider](https://tech-insider.org/codex-vs-cursor-vs-claude-code-2026/)); one login should cover the agent. Company size drives choice: small firms pick Claude Code, enterprises default to Copilot via procurement (Pragmatic).
9. **Multi-provider freedom as insurance.** OpenCode's 200k stars and LogRocket #1 are a reaction to lock-in events; Zed and Devin Desktop now host *any* agent over ACP.
10. **Headless/CI programmability is assumed**: `claude -p --bare --output-format json`, `codex exec --json`, OpenCode's HTTP/SSE server, Pi's RPC mode; bare mode will become Claude Code's `-p` default ([headless doc](https://code.claude.com/docs/en/headless)).
11. **Observability of what the agent did.** Per-task cost in JSON output, `/workflows` token trees, Codex thread-cost visibility (0.148.0) and Copilot per-model token breakdowns (Aug 11) all shipped within 60 days: "show me the bill and the transcript".
12. **Trust lags usage.** Latest published SO data (2025): 84% use AI tools, 46% distrust output, 3% "highly trust", 66% frustrated by "almost right" code ([SO 2025](https://survey.stackoverflow.co/2025/ai)); JetBrains: 90% weekly use. That gap is the product opportunity.

## 4. The orchestration frontier

### 4.1 How leaders surface multi-agent work (verified against docs/changelogs)

**Claude Code** has five parallelism primitives, each with a different "who holds the plan" answer ([workflows doc](https://code.claude.com/docs/en/workflows)):
- *Subagents*: since 2.1.232 "fork" subagents inherit the conversation and prompt cache, and interactive spawns run in the background by default ([CHANGELOG](https://github.com/anthropics/claude-code/blob/main/CHANGELOG.md)).
- *Agent teams* (experimental env flag): lead + teammates, shared task list with file-locked claiming, JSON mailboxes, in-process panel or tmux/iTerm2 panes, plan-approval gates, `TeammateIdle`/`TaskCompleted` hooks; one team per session, no nesting, in-process teammates don't survive `/resume` ([agent-teams doc](https://code.claude.com/docs/en/agent-teams)).
- *Dynamic workflows* (v2.1.154+): Claude writes a JavaScript orchestration script the runtime executes in the background; 16 concurrent agents, 1,000 agents/run, resumable within the session, `/workflows` shows per-phase tokens, saved scripts become commands, `ultracode` effort auto-plans them.
- *Agent view* (v2.1.140, research preview): a **per-user supervisor daemon** hosts sessions that "survive terminal closure and sleep" but "stop if the machine shuts down"; `claude --bg`, `claude agents`, `claude attach`, worktree auto-isolation, idle sessions parked after ~1h ([agent-view doc](https://code.claude.com/docs/en/agent-view)).
- *Cross-session messaging* (v2.1.224+): `ListAgents`/`SendMessage` over local Unix sockets, and **across machines through Anthropic's relay when both ends run Remote Control**; `isolatePeerMachines` gates cross-machine sends; inbound messages can never approve permissions ([cross-session doc](https://code.claude.com/docs/en/cross-session-messaging)).
- Surfaces: *Remote Control* (2026-02-25; `/rc` + QR; phone/web steer a local session; auto-reconnect after sleep; Trusted Devices beta; transcript mirrored to Anthropic; ZDR orgs excluded) ([doc](https://code.claude.com/docs/en/remote-control)); *cloud sessions* (`claude --cloud`, one-way `--teleport`, routines, `/autofix-pr`) ([doc](https://code.claude.com/docs/en/claude-code-on-the-web)); *self-hosted environments* (Team/Enterprise beta; runners poll a queue, sessions requeue after ~60s of missed polls) ([doc](https://code.claude.com/docs/en/self-hosted-environments)); *channels* (Telegram/Discord/iMessage push events into a live session) ([doc](https://code.claude.com/docs/en/channels)); `/goal` objectives with backoff check-ins (2.1.239). `/ultraplan` was removed in favour of auto-created cloud environments ([gradually.ai](https://www.gradually.ai/en/changelogs/claude-code/), **secondary**). The API-level *Managed Agents* beta adds server-side sessions with persistent threads and multi-agent orchestration ([overview](https://platform.claude.com/docs/en/managed-agents/overview)).

**Codex**: MultiAgentV2 landed in CLI 0.128.0 (2026-04-30): `spawn_agent`/`send_message`/`followup_task`/`wait_agent`/`list_agents`/`close_agent`, path-based addressing, `max_threads` 6 and `max_depth` 1 defaults, `fork_turns` semantics, TOML roles ([Codex KB](https://codex.danielvaughan.com/2026/05/03/codex-cli-multiagentv2-custom-roles-thread-orchestration-parallel-workflows/)). The desktop app (Feb 2026; merged into the ChatGPT app July 9) is the "command center" for parallel worktree agents, `codex cloud` handoff, Automations with cloud triggers and Codex Remote on iOS; 0.149.0 (Aug 20) added an agents dashboard and `codex queue`, 0.148.0 session forking and thread-cost visibility ([changelog](https://learn.chatgpt.com/docs/changelog), [Wikipedia](https://en.wikipedia.org/wiki/Codex_(AI_agent))).

**Cursor**: the Agents Window runs agents "locally, in worktrees, in the cloud, and on remote SSH"; Cloud Agents (3.5, May 20) on isolated VMs; Aug 19 "subscriptions" let cloud agents watch PRs, Slack and cron, spawn subagents on isolated VMs and pursue `/goal`; Aug 13 warm "Builds" claim 3x faster TTFT ([changelog](https://cursor.com/changelog)).

**Devin**: parallel sessions (Feb), Managed Devins coordinator/child VMs (Mar), Fusion lead/sidekick (Jul 13), Devin Desktop as an ACP multi-agent host. **Warp Oz** runs Claude Code/Codex skills as cloud agents with cron and enterprise self-host. **Amp** runs threads on "orbs" (remote machines) with multiplayer workspace threads and Oracle/Librarian/Painter subagents. **OpenCode** exposes a headless HTTP/OpenAPI/SSE server with multi-client parent/child sessions, basic auth and a `/tui` endpoint for remote drivers ([server doc](https://opencode.ai/docs/server/)). **Copilot** cloud agent: one branch, one PR, 59 minutes per task; Agent Plugins 1.0 (Aug 12); shared agentic work in Teams/Slack (Aug 21) ([changelog](https://github.blog/changelog/label/copilot/)). **Third-party layer**: Conductor (Mac, free, worktree-isolated Claude Code/Codex/Cursor) ([conductor.build](https://conductor.build/)), Vibe Kanban (28k stars), Claude Squad (8k); Happy (23k stars, E2E-encrypted phone control, "no telemetry") ([repo](https://github.com/slopus/happy)); Omnara, now "the open-source alternative to Claude Managed Agents" with agent state committed atomically to Postgres, several machines per agent and crash recovery ([repo](https://github.com/omnara-ai/omnara)).

### 4.2 Real demand signals for a long-lived, multi-machine daemon

- **Sessions that survive laptop sleep / terminal close.** Anthropic's Remote Control doc concedes: "Local process must keep running… To keep a session running on a remote machine after you disconnect from SSH, start it inside tmux or screen" ([doc](https://code.claude.com/docs/en/remote-control)). Agent view's daemon survives sleep but "stop[s] if the machine shuts down" and parks idle sessions after ~1h. A cottage industry of tmux/mosh guides exists for this reason ([gist](https://gist.github.com/alxpck/d1e86d9a62e3fc5cf6c1ce52d0a02b10), [dyb.eu](https://dyb.eu/blog/en/claude-code-tmux-stop-losing-your-terminal-sessions-every-time-your-mac-sleeps/), [aq.dev](https://aq.dev/guides/keep-claude-code-running-after-closing-laptop/)); Codex's "auto-resume when usage limit resets" is open ([#21073](https://github.com/openai/codex/issues/21073)).
- **Run on a remote box, attach from laptop/phone.** Codex's two most-upvoted requests ever were "Remote Development" (875) and "Remote Control" (542); the still-open "headless remote Linux hosts for Codex mobile without the desktop app online" ([#23200](https://github.com/openai/codex/issues/23200)) is precisely the daemon gap. OpenCode's #7790 (110) and Happy's 23k stars are the same demand from the open side.
- **Cross-machine teams.** Claude Code's cross-machine messaging exists only via Anthropic's relay, plain text only, only while both ends hold Remote Control, and off if telemetry is off. Config/session sync across machines is a recurring request ([#39457](https://github.com/anthropics/claude-code/issues/39457), [#72578](https://github.com/anthropics/claude-code/issues/72578)). Self-hosted environments prove enterprises want compute in their network, yet orchestration still runs through Anthropic's control plane and ZDR customers are excluded.
- **Durable audit of agent effects.** EU AI Act obligations bit on 2026-08-02 with a 6-month log-retention expectation for high-risk uses ([dev.to](https://dev.to/igorganapolsky/your-compliance-team-will-ask-for-an-ai-agent-audit-trail-before-august-2-heres-the-part-most-h2n)); enterprise checklists call "SIEM-connected audit logging" non-negotiable ([Northflank](https://northflank.com/blog/enterprise-ai-coding-agent-deployment)). Vendors answer with OTel export and admin logs (Claude managed settings, Cursor/Factory Enterprise audit logs, Copilot usage-metrics API), yet a fresh Claude Code bug reads "No audit trail for retention cleanup — deleted sessions leave no log" ([#87889](https://github.com/anthropics/claude-code/issues/87889)). Nobody ships a local, tamper-evident **effect ledger** (what changed, where, under which permission, by which agent) that survives across machines.

**Why a daemon is a differentiator, not a curiosity.** Every leader's persistence story is (a) a per-machine supervisor that dies on shutdown and parks after an hour, (b) a vendor VM that expires on inactivity and shares rate limits with everything else, or (c) a relay that still needs the local process alive. The open slot is a *self-hosted control plane*: a daemon that owns sessions independent of any terminal, resumes them across the user's machines, exposes an OpenCode-style HTTP/SSE API plus TUI/phone attach, treats cross-machine messaging as a peer protocol rather than a vendor relay, and records every effect durably. The top issues on Codex and OpenCode ask for it, Anthropic's own "use tmux" guidance implies it, and the compliance calendar demands it — and it does not exist off-the-shelf with vendor-neutral model access.
