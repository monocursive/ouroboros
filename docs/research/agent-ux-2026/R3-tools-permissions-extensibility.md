# R3 — Tool surface, tool-call mechanics, permissions, and extensibility of coding agents

Research date: 2026-08-22. Sources are official docs/repos fetched today unless marked third-party; claims I could not confirm are marked **unverified**. Agents covered: Claude Code, OpenAI Codex CLI, Gemini CLI, OpenCode, Amp, Pi, Cursor, Aider, Cline, Factory Droid, Kiro, GitHub Copilot CLI, Crush, Goose, and Zed/ACP.

## 0. Headline findings

1. **Tool sets have converged** on ~8 primitives (read, write, exact-string edit, shell, grep, glob, web fetch/search, subagent) plus a skills loader; differentiation is in result handling, permissions, and context.
2. **Two edit dialects dominate**: exact `old_string/new_string` replacement (Claude Code, Gemini, OpenCode, Pi, Amp, Goose) and Codex's V4A `apply_patch` (also a second tool in OpenCode, Cline, Factory). Aider remains the reference for fuzzy application and edit-format research.
3. **Permissions moved from prompts to policy + sandbox + classifier.** Claude Code, Codex, Cursor, Gemini, Factory and Kiro all ship OS-level sandboxes and/or model-based reviewers in 2026; Amp and Pi ship no prompts at all and leave containment to the user.
4. **ACP is the lingua franca for editor embedding** (version 1, JSON-RPC over stdio): 37 native agents plus adapters for Claude Code, Codex and Pi; clients include Zed, JetBrains, four Neovim plugins, Emacs, VS Code, Obsidian, Qt Creator. Codex adds a richer first-party JSON-RPC app-server; Claude Code exposes `stream-json` and the Agent SDK.
5. **Cross-agent conventions**: `AGENTS.md` (everyone except Claude Code, which needs `@AGENTS.md`), Agent Skills in `.agents/skills/`, and hook JSON shapes copied from Claude Code's `PreToolUse`/`permissionDecision` contract (Codex, Factory, Kiro; Gemini with renamed events).

### 1.2 How edits are expressed

- **`str_replace` family.** Claude Code's `Edit` is "exact string replacement (no regex/fuzzy)" with three checks: the file must have been `Read` in the conversation, `old_string` must match exactly once unless `replace_all`, and a file changed since the read is re-read and a stale `old_string` fails; "a single whitespace difference fails the match" ([tools-reference](https://code.claude.com/docs/en/tools-reference)). This mirrors the API `str_replace_based_edit_tool` ([text editor tool](https://docs.claude.com/en/docs/agents-and-tools/tool-use/text-editor-tool)) and Amp's tutorial primitive `edit_file(old_str,new_str)` ([How to build an agent](https://ampcode.com/how-to-build-an-agent)).
- **V4A `apply_patch` (Codex).** `*** Begin Patch` / `*** End Patch`; `*** Add File:`, `*** Delete File:`, `*** Update File:` with optional `*** Move to:`; hunks start with `@@` (optionally naming the enclosing class/function), lines prefixed space/`-`/`+`, `*** End of File` for trailing edits; no line numbers, "3 lines of code immediately above and 3 lines immediately below each change" ([GPT-4.1 guide](https://developers.openai.com/cookbook/examples/gpt4-1_prompting_guide)). The Responses API exposes `{"type":"apply_patch"}` with `create_file`/`update_file`/`delete_file` and the client reports `apply_patch_call_output` `status: completed|failed`; "your patch harness is responsible for interpreting the V4A diff format" ([guide](https://developers.openai.com/api/docs/guides/tools-apply-patch)). OpenAI also found Aider's SEARCH/REPLACE and a pseudo-XML format "both had high success rates" because they show exact old and new text. The grammar file lives in `openai/codex` under `codex-rs/apply-patch` (exact path **unverified**; documented paths 404 today).
- **Aider's fuzzy ladder** (`editblock_coder.py`): `perfect_replace` → `perfect_or_whitespace` (re-indent) → `try_dotdotdots` (`...` elision) → `replace_closest_edit_distance` (`SequenceMatcher`, `similarity_thresh = 0.8`); failures emit `SearchReplaceNoExactMatch` plus `find_similar_lines` ([source](https://github.com/Aider-AI/aider/blob/main/aider/coders/editblock_coder.py)). Aider reports "experiments where flexible patching is disabled show a 9X increase in editing errors" and udiff cut GPT-4 Turbo laziness from 20% to 61% ([unified diffs](https://aider.chat/2023/12/21/unified-diffs.html)).
- **Gemini's model-assisted repair.** On mismatch, `editCorrector.ts` applies regex `unescapeStringForGeminiBug` then asks the model (`CODE_CORRECTION_SYSTEM_PROMPT`, JSON schema) to repair the string, with a 50-entry LRU cache ([source](https://github.com/google-gemini/gemini-cli/blob/main/packages/core/src/utils/editCorrector.ts)).
- **Guards in one line:** read-before-edit and modified-since-read (Claude Code), uniqueness/`replace_all`/`allow_multiple` (Claude Code, Gemini), fuzzy ladders (Aider), LLM repair (Gemini), `doom_loop` after 3 identical calls (OpenCode), snapshots before edits (Claude Code, Gemini, Cline; §3).

### 3.2 Details worth knowing

- **Claude Code Bash rules**: `Bash(ls *)` enforces a word boundary (`ls -la`, not `lsof`); one `*` spans arguments; compound commands split on `&&`, `||`, `;`, `|`, `|&`, `&`, newlines and every part must match; `timeout/time/nice/nohup/stdbuf/command/builtin/noglob` and bare `xargs` are stripped; redirect targets are checked as writes; `Bash(command:rm *)` is rejected as bypassable. Deny/ask rules may use tool-name globs, allow rules may not. Project allow rules wait for workspace trust ([permissions](https://code.claude.com/docs/en/permissions)).
- **Claude Code auto mode** blocks "anything that escalates beyond your request, targets unrecognized infrastructure, or appears driven by hostile content Claude read"; it trusts only remotes configured at session start, reviews `SendMessage` content, and treats stated boundaries ("don't push") as block signals; `claude auto-mode defaults` prints the rules ([permission modes](https://code.claude.com/docs/en/permission-modes)). Sandbox violations trigger a `dangerouslyDisableSandbox` retry that admins disable with `allowUnsandboxedCommands: false`; sandboxing "reduces permission prompts by 84%" ([post](https://www.anthropic.com/engineering/claude-code-sandboxing)).
- **Codex granular approvals** split prompts into `sandbox_approval`, `rules`, `mcp_elicitations`, `request_permissions`, `skill_approval`; `requirements.toml` pins policy and `allow_managed_hooks_only` ([config ref](https://developers.openai.com/codex/config-reference)).
- **Cursor** admits its classifier "can make mistakes" and its denylist was bypassed with obfuscated commands ([Backslash](https://www.backslash.security/blog/cursor-ai-security-flaw-autorun-denylist)); sandboxed agents "stop 40% less often" ([blog](https://cursor.com/blog/agent-sandboxing)).

## 5. Context-engineering mechanics

- **Startup context (Claude Code).** Representative figures: system prompt ≈4,200 tokens, `MEMORY.md` (first 200 lines/25 KB), environment, MCP tool *names only*, skill descriptions, the CLAUDE.md hierarchy, git status; nested CLAUDE.md and `paths:` rules load when matching files are read; CLAUDE.md arrives "as a user message after the system prompt" ([context window](https://code.claude.com/docs/en/context-window), [memory](https://code.claude.com/docs/en/memory)).
- **Compaction.** Claude Code "clears older tool outputs first, then summarizes"; root CLAUDE.md, memory and MCP tools reload, the skill listing does not; thrashing detection halts repeated compaction. Window via `/autocompact 500k`, `--autocompact`, `CLAUDE_CODE_AUTO_COMPACT_WINDOW`, `CLAUDE_AUTOCOMPACT_PCT_OVERRIDE`; Sonnet 5 compacts "at about 967K tokens"; `/rewind` offers "Summarize from here / up to here" ([how it works](https://code.claude.com/docs/en/how-claude-code-works), [model config](https://code.claude.com/docs/en/model-config), [checkpointing](https://code.claude.com/docs/en/checkpointing)). Codex: `model_auto_compact_token_limit(_scope)`, `thread/compact/start`. Gemini: `model.compressionThreshold`=0.5, `PreCompress` hook. OpenCode: `experimental.session.compacting` hook. Pi: compaction "lossy. The full history remains in the JSONL file", `/tree` branching. Amp replaced compaction with **Handoff** because it produced "summary on top of summary" ([Handoff](https://ampcode.com/news/handoff)).
- **Prompt caching.** Claude Code layers system prompt (tools, output style) → project context → conversation. Invalidators: model/effort switch, fast mode, MCP changes when tools are in the prefix, bare-name tool denies, compaction, upgrades; cache-safe: plan mode, skills, permission-mode switches, `/rewind`. TTL 1 h on subscriptions, 5 min on API; forks share the parent prefix ([prompt caching](https://code.claude.com/docs/en/prompt-caching)). The team alerts on cache hit rate and built `defer_loading` stubs to keep the prefix stable ([Lessons](https://claude.com/blog/lessons-from-building-claude-code-prompt-caching-is-everything)); Manus reports 0.30 vs 3 USD/MTok cached vs uncached ([Manus](https://manus.im/blog/Context-Engineering-for-AI-Agents-Lessons-from-Building-Manus)).
- **Context meter.** Claude Code `/context`, `/usage` attribution by skill/subagent/MCP server, statusline `current_usage`; ACP `usage_update`; Amp "Explain Usage" (Aug 2026).
- **Retrieval.** Anthropic recommends agentic grep/glob search before semantic search ([Agent SDK post](https://claude.com/blog/building-agents-with-the-claude-agent-sdk)); Aider's repo map ranks tree-sitter symbols under a 1k-token default budget ([repomap](https://aider.chat/docs/repomap.html)); Claude Code adds LSP plugins ([costs](https://code.claude.com/docs/en/costs)).
- **Minimal prompts.** Pi's four-tool prompt is reported (third-party, **unverified**) at under ~1,000 tokens ([explainx](https://explainx.ai/blog/pi-minimal-agent-harness-mario-zechner-guide-2026)).

## 8. Synthesis

### (a) Table stakes for a top-5 agent in 2026

1. **Tools:** read (with offset/limit, images, PDFs), write, exact-string edit with uniqueness + read-before-edit guards, ripgrep search, glob, shell with timeout/background/PTY, web fetch + search, subagent spawn with isolated context, skills loader, ask-user. Every leader has all of these; V4A `apply_patch` as a *second* edit tool is now common (Codex, OpenCode, Cline, Factory).
2. **Result handling:** hard caps on shell and MCP output with spill-to-file + preview (Claude Code 30 KB/25k tokens, Codex `tool_output_token_limit`, Gemini 40k chars, ACP `outputByteLimit`), background processes, parallel tool calls.
3. **Permissions:** allow/ask/deny rules with command-prefix and path globs, a per-session "always" that persists per repo, protected paths (`.git`, own config), a plan/read-only mode, an accept-edits mode, and a full-bypass mode that refuses to run as root (Claude Code) or is labeled dangerous (Codex, Factory, Cline).
4. **Sandbox:** macOS Seatbelt and Linux bubblewrap/Landlock+seccomp with a domain-allowlisting proxy is now standard (Claude Code, Codex, Cursor, Factory, Gemini via containers). Shipping without one means either prompting for everything or being Amp/Pi (no prompts, user-provided containment).
5. **Extensibility:** MCP stdio+HTTP with OAuth/DCR; hooks with a `PreToolUse → allow|deny|ask + updatedInput` contract; Agent Skills standard reading `.agents/skills/`; `AGENTS.md`; markdown subagent definitions; a headless JSON stream; ACP.
6. **Context:** instruction-file hierarchy with lazy nested files, auto-compaction with a configurable window and a visible meter, prompt-cache-aware request layout, deferred tool schemas.

### (b) Differentiators

- **Claude Code:** classifier-based auto mode as the default; the richest hook surface (30 events, five handler types including `prompt`/`agent` hooks, `PostToolBatch`, `FileChanged`); MCP tool search by default; credential masking with TLS-terminating proxy; resumable/background subagents with `SendMessage`; `Workflow` dynamic harnesses; plugin marketplaces with LSP/monitor bundles.
- **Codex:** V4A patches; app-server with per-turn `sandboxPolicy`/`approvalPolicy`, `turn/steer`, `thread/fork`, `acceptWithExecpolicyAmendment`; `approvals_reviewer = "auto_review"`; granular approval categories; `requirements.toml` enterprise pinning; skills metadata budget (2%/8k chars).
- **Gemini CLI:** TOML policy engine with tiered priorities and mode hierarchy; model-assisted edit repair; six Seatbelt profiles and gVisor; `BeforeModel/AfterModel/BeforeToolSelection` hooks; A2A remote subagents; proxied FS in ACP mode.
- **Cursor:** plain-English `allow_instructions`/`block_instructions` for the classifier; overlay-FS hiding of `.cursorignore` files in the Linux sandbox; `stop` hooks that auto-submit follow-ups.
- **OpenCode:** `doom_loop` and `external_directory` as first-class permissions; full HTTP/SSE server + SDK; plugin hooks over every event; reads Claude skills/agents.
- **Factory:** risk-tiered autonomy with org-clamped maximum and a three-list command policy; `stream-jsonrpc`; context budgets for AGENTS.md.
- **Kiro:** capability rules with deny-override across six scopes and repo-external workspace rules; ACP vendor extensions done by the book (`_kiro.dev/*`).
- **Amp:** zero-prompt execution plus toolboxes, plugins that can classify tool calls with `amp.ai.ask()`, Oracle/Librarian subagents, Handoff instead of compaction, orbs.
- **Pi:** four tools, ~1k-token prompt, session trees, everything else via TypeScript extensions and JSONL RPC.
- **Aider:** the only one with published edit-format benchmarks and a fuzzy application ladder; architect/editor model split; repo map.

### (c) Mechanics worth copying (by product)

1. **Claude Code:** Bash rule matching (word-boundary `*`, compound splitting with per-subcommand rule saving, wrapper stripping, redirect checks, refusing `Bash(command:...)`); spill large outputs to a file with a preview; `Tool(param:value)` deny/ask specifiers; deferred tool stubs and never touching the cached prefix mid-session.
2. **Codex:** V4A patches anchored by `@@` scope and `*** End of File`; `acceptWithExecpolicyAmendment` turns an approval into a rule; per-turn sandbox/approval overrides in the protocol; optional auto-review subagent.
3. **Gemini:** policy priorities (`tier_base + priority/1000`, admin wins, approvals in `default` carry into `autoEdit`/`yolo`); model-based edit repair.
4. **Kiro:** deny-override across scopes with repo-external workspace rules; per-sub-command evaluation of chained commands.
5. **Factory:** a blocklist that survives `--skip-permissions-unsafe`; `droid exec` read-only by default with `--auto low|medium|high`.
6. **Cursor:** surface the violated sandbox constraint and recommend escalation; Bash/Explore/Browser subagents that quarantine noisy output.
7. **Aider:** fuzzy application with an explicit 0.8 threshold and "similar lines" feedback; architect/editor split.
8. **OpenCode:** `doom_loop` and `external_directory` as permission keys.
9. **Amp:** Handoff (curated prompt + file list into a fresh thread); toolboxes (`describe`/`execute` executables) as a zero-framework tool interface.
10. **ACP:** tool `kind` taxonomy, `diff`/`terminal` blocks, `allow_always`, replay on `session/load`, `_meta` extensions — native support buys Zed, JetBrains, Neovim, Emacs and VS Code clients.

### (d) Mistakes to avoid, with evidence

- **Denylist-only auto-run.** Cursor's denylist was bypassed by obfuscated commands ([Backslash](https://www.backslash.security/blog/cursor-ai-security-flaw-autorun-denylist)); Claude Code documents why argument-constraining rules like `Bash(curl http://github.com/ *)` "are fragile" (options, protocol, redirects, variables) and recommends deny + `WebFetch(domain:)` ([permissions](https://code.claude.com/docs/en/permissions)). Use allowlists + sandbox + classifier; reserve blocklists for catastrophes (Factory).
- **Single-axis sandboxes.** Anthropic: "effective sandboxing requires both" filesystem and network isolation ([post](https://www.anthropic.com/engineering/claude-code-sandboxing)); Factory warns allowed domains are exfiltration channels ([sandbox](https://docs.factory.ai/autonomy-and-safety/sandbox.md)).
- **Trusting repo-supplied config.** Claude Code gates project allow rules on workspace trust, ignores `mask`/`tlsTerminate` in project settings, and warns that `-p` runs a clone's hooks/MCP unless `--bare`; Kiro keeps workspace rules outside the repo ([headless](https://code.claude.com/docs/en/headless), [Kiro](https://kiro.dev/docs/permissions/)).
- **Unbounded tool output and tool lists.** Every leader caps output; Anthropic measured 72K tokens of tool definitions before tool search ([Advanced tool use](https://www.anthropic.com/engineering/advanced-tool-use)).
- **Exact-match edits with no recovery path.** Claude Code's "File has been unexpectedly modified" false positives on CRLF/format-on-save ([issue #13456](https://github.com/anthropics/claude-code/issues/13456)); Aider: disabling flexible patching multiplies errors 9×; Gemini added LLM repair. Ship whitespace tolerance or a "similar lines" error at minimum.
- **Changing the cached prefix mid-session** (tools, model, system prompt): the documented cause of slow, expensive turns ([prompt caching](https://code.claude.com/docs/en/prompt-caching)); Manus calls cache hit rate "the single most important metric."
- **Built-in TODO tools and bloated instruction files.** Pi dropped TODOs ("they confuse models"); Claude Code disabled `TodoWrite`/`TaskCreate` by default on its newest models and says CLAUDE.md beyond ~200 lines "reduce[s] adherence" ([tools-reference](https://code.claude.com/docs/en/tools-reference), [memory](https://code.claude.com/docs/en/memory)).
- **Lossy compaction as the only long-context strategy.** Amp replaced it with Handoff; Claude Code clears tool outputs first, re-injects CLAUDE.md, and detects thrashing; Cognition: compression "is hard to get right."
- **Parallel subagents without shared decisions** (Cognition's Flappy Bird example); Claude Code mitigates with context-inheriting forks and adversarial verification, and says dynamic workflows are "not needed for every task."
- **Classifier-only safety.** Cursor: the classifier "can make mistakes"; Claude Code: auto mode "does not guarantee safety" and is paired with deny rules, protected paths, and the sandbox.
