notes
- The trace data is 0x4f4a. A stop on a number this filter never traces, with
  other data, was asked for by a child's own SECCOMP_RET_TRACE and is continued:
  the call then runs, where with no tracer it would have returned ENOSYS. It is
  neither a result nor a loss. The same stop with this filter's data means the
  installed program is not this one: an unexpected_trace_stop gap.
- prctl(PR_SET_SECCOMP) is not traced: it cannot create a notification listener.
- A child's own filter that refuses a call (errno, trap, kill) before this one
  stops it hides a call that had no effect: a named exclusion, not a gap.
- With no tracer attached, every TRACE verdict fails the call with ENOSYS: the
  observer's death, and a CLONE_UNTRACED descendant, fail closed.
- A return carrying a kernel restart code (ERESTARTSYS, ERESTARTNOINTR,
  ERESTARTNOHAND, ERESTART_RESTARTBLOCK) is not a result: the thread is
  single-stepped to the kernel's decision. A re-entry of the call is its one
  result; EINTR at a handler's entry is the result; a death is neither a
  result nor a loss (the call did nothing); anything else is a
  restart_unresolved gap of the call's classes.
- A restart decided at a handler's entry is believed only at the re-entry
  itself, because the handler's frame, which rt_sigreturn restores, is the
  program's to rewrite. Until then the thread runs; its next entry stop at
  the call's own instruction is the re-entry, any other entry stop first is
  a restart_unresolved gap (so a covered call made inside an SA_RESTART
  handler costs one), and its end first is a restart_unresolved gap when
  the frame decided (ERESTARTSYS) and nothing when the code alone did
  (ERESTARTNOINTR). A kill at the re-entry is counted once.
- A non-leader exec destroys the leader: whatever the leader had in flight
  is an entry_abandoned gap of its classes, never paired with the exec's
  own syscall exit, whether or not the exec's entry could be followed.
- A tracee killed at its entry stop before the observer resumed it made no
  call (the kernel skips it): neither a result nor a loss. Killed at its exit
  stop before the return was read, the call ran: entry_abandoned of its own
  classes.
