# Web UI and TUI review — design, usability, categorisation, parity

Date: 2026-09-15. Branch `dev` at `7bea32f5`. Client `ouro 0.1.7`.

Method: read of `tui/src/` (keymap, key dispatch, palette, overlays, editor, help,
settings) and `lib/ouroboros/web/` (router, deck, composer, rail, cells, new-session,
settings, status, audit, `app.js`); the two-day-old product captures under
`website/public/demos/`; and live runs of both surfaces — the packaged `ouro` and
`ouro web` against an isolated data directory, and a second pair attached to the
Playwright fixture runtime (`test/support/browser_runtime.exs` with `OUROBOROS_GATEWAY=1`),
which is the only way to open a seeded session without credentials. Every finding below
names the code that produces it; the ones marked *(live)* were also reproduced on screen.
The keyboard reference is opencode's published defaults (`opencode.ai/docs/keybinds`).

---

## 1. Summary

Both surfaces are carefully built where they have been built: the transcript projection
is shared and corpus-locked, the approval card and modal invent nothing, "absent, not
defaulted" is held end to end, and every control is gated on what the runtime actually
serves. The problems are structural rather than cosmetic:

1. **The TUI's key layer is split in two and the wrong half is documented.** The composer
   owns the keyboard whenever the Sessions tab is showing, so the single-letter and digit
   keys (`1-7`, `Tab`, `j/k`, `i`, `s`, `a`, `n`, `x`, `q`) that the docs and the `?` panel
   describe as session keys are either dead or reachable only from the three secondary
   tabs — and no tab bar is ever drawn, so those tabs are invisible as well.
2. **The TUI's discovery surfaces disagree with each other.** The palette has two groups
   and prints each heading three times; `/diff` and `/raw` are in the palette but in
   neither the `/` completion menu nor the `?` panel; `ctrl+d` has no hint anywhere but
   `/keys`; the peek overlay's hint names a key that does the opposite; `docs/TUI.md`
   names `Ctrl-E` for an editor bound to `ctrl+g`.
3. **The web is a different product, not a second client.** Against the TUI's 41 palette
   commands and 40 slash verbs the web has one shortcut (`/` to focus search), no
   palette, no copy, no event ledger, no steer/fork/rewind/compact/handoff/context, no
   per-session model change, no operator shell, and no help. Its own navigation has no
   hub: only the deck carries the topbar, the connection pill and the bell; `/status` is
   reachable from nowhere.
4. **Two small regressions undercut the web deck.** The rail's live-activity line can never
   render (`activity/1` guards on `is_list` while `:cells` is a map), and the session
   vitals plus the **auto-approve toggle** sit inside a disclosure named
   `ouro-vitals-mobile` on every viewport, which also strands seven CSS rules.

The rest of this document is the evidence, then a proposed key map and categorisation
that would bring the two surfaces to parity.

## 2. TUI

### 2.1 Screen states and reachability

`Tab::ALL` is four tabs — Dashboard, Sessions, Upgrade, Logs (`tui/src/ui/app/mod.rs:130-152`).
The header prints the current tab's title as a subtitle (`Runtime & distribution: Dashboard`)
and never the list, so nothing on screen says four tabs exist *(live)*.

Key dispatch (`tui/src/ui/app/keys.rs:8-166`) reaches the composer at `:116-119` whenever
`sessions.composer.is_some() && tab == Sessions`, and `open_session_on` always recreates the
composer for the only plane there is (`tui/src/ui/app/streaming.rs:540-546`). Consequences:

| Key | Documented as | Actually |
|---|---|---|
| `1`–`7` | "runtime tabs" (`?` panel, `view.rs:3418`; `docs/TUI.md:1957`) | four tabs; `5`–`7` swallowed (`keys.rs:135-141`); none reachable with a session open |
| `Tab` / `BackTab` | tab cycle | only from home with an empty draft (`keys.rs:123-129`); otherwise completion |
| `i`, `s`, `a` | composer / steer / approval (`docs/TUI.md:1957-1959`) | dead: the handlers return unless `tab == Sessions`, the one state that cannot reach them (`session.rs:561`, `:2546`) |
| `q`, `r`, `j/k/h/l`, `n`, `x` | session keys | only on Dashboard/Upgrade/Logs; `q` bypasses `[keys] quit` (`keys.rs:147`) |
| `Esc` with text, idle | "closes the composer, keeping the draft" (`docs/TUI.md:2161`) | nothing (`overlays.rs:1706-1715`) |
| `Space` in the picker | "peeks without leaving the list" (`docs/TUI.md:2285`) | replaces the picker; `Enter` closes the peek, although its hint says "enter opens" (`overlays.rs:1008`, `panels.rs:490`) |

The "session open, composer closed" state the docs describe does not exist, and
`escape()`'s composer-closing branch (`keys.rs:499-507`) is unreachable.

### 2.2 Palette *(live)*

`Command::ALL` has 41 entries in two groups, "Coding" (35) and "Runtime & distribution" (6)
(`tui/src/ui/app/overlays.rs:163-243`). Rows are drawn in `ALL` order with a heading on every
group change and no sort (`view.rs:1235-1247`); the group flips six times, so a scrolled
palette shows each heading three times. Other issues:

- Two rows, one verb: "Runtime & distribution" and "Nodes" both map to `/runtime` and
  both select the Dashboard tab (`overlays.rs:1178-1181`).
- Label and shortcut collide on narrow palettes: the gap is
  `content_width - (label + shortcut)` with no truncation, so
  "Copy last agent message as source Markdown" renders as `…Markdown/copy ra` at 140 columns.
- State-blind rows: "Interrupt the running turn" and "Steer the running turn" are gated on
  transport capability only (`overlays.rs:401-438`), so both are offered on an idle or ended
  session.
- Settings and MCP are "Runtime & distribution"; Keyboard shortcuts is "Coding".
- Filtering also matches the group name, so `co` returns all 35 Coding rows.

### 2.3 Slash verbs and completion

The dispatcher (`session.rs:2268-2440`) accepts 40 verbs; the `/` completion table
(`editor.rs:24-76`) lists 39; the `?` panel's COMMANDS block is derived from that table.
`/diff`, `/changes`, `/raw`, `/keymap`, `/usage` are in neither, so `/di` offers nothing.

Two behaviours worth changing:

- **Enter never accepts a highlighted completion; only Tab does** (`editor.rs:353`). On the
  home screen, typing `/ke` and pressing Enter submitted "/ke" as the first task and opened
  the ChatGPT device-code sign-in *(live)*; in a session an unknown verb is sent to the
  model as a turn (`session.rs:1936-1948`, no unknown-verb arm). opencode, Claude Code and
  Codex all select on Enter.
- **Bare `/theme` cycles and writes `config.toml` immediately** (`session.rs:2306`,
  `mod.rs:1180`), with only a one-line notice. A preview-then-save, or a list to pick from,
  is what every neighbour does *(live: this review changed the reviewer's theme)*.

### 2.4 Keyboard against opencode

Same as opencode, keep: leader `ctrl+x`; `ctrl+p` palette; `esc` interrupt; `<leader>n`
new; `<leader>l` sessions; `<leader>e` editor; `<leader>y` copy; `<leader>q` quit;
`pageup`/`pagedown`; `up`/`down` history; `ctrl+j` newline; the whole readline set
(`ctrl+a/e/k/u/w`, `alt+b/f/d`).

Divergences that will bite a user arriving from opencode / Claude Code / Codex:

| Key | opencode | Ouroboros | Note |
|---|---|---|---|
| `ctrl+c` | exit (and clear input) | never exits with a session open (`session.rs:2444-2487`) | no exit key such a user will find; `ctrl+q` may be XON on `ixon` terminals |
| `ctrl+d` | exit / delete | quit dialog on empty prompt, delete-forward with text (`keys.rs:70`, `editor.rs:383`) | two meanings, no hint anywhere but `/keys` |
| `ctrl+g` | messages first | opens `$EDITOR` on the draft (`keymap.rs:275`) | `ctrl+g` is *abort* in readline and every shell; `docs/TUI.md:1964` says `Ctrl-E` |
| `<leader>x` | **export** | **end or remove session** | the most dangerous collision in the map; a confirm dialog is the only guard |
| `<leader>s` | status | steer | `alt+enter` already steers |
| `<leader>a` | agent list | approval | fine to keep; the approval verb matters more here |
| `<leader>r` | redo | save the rule a refused `!` named | |
| `<leader>g` | timeline | — | backtrack is `esc esc` only |
| `<leader>m` / `<leader>t` / `<leader>c` | model / theme / compact | — | slash-only here |
| `<leader>b` | toggle sidebar | — | the rail cannot be hidden |
| `ctrl+r` | rename session | — | rename exists only on the web |
| `ctrl+t` | variant cycle | plan panel | Claude Code parity; defensible |
| `tab` / `shift+tab` | agent cycle | completion / tab cycle | fine |
| `f2` | model cycle | starter prompt | fine on home only |
| `ctrl+z` | suspend | — | missing |
| `home` / `end` | messages first / last | line start / end | readline; fine |
| `ctrl+-` / `ctrl+.`, `<leader>u/r` | input undo / redo | — | no undo; single-slot kill ring (`editor.rs:557-576`) |
| `?`, `,` on an empty prompt | — | help / settings (`keys.rs:99-107`) | you cannot start a message with `?` or `,`; `?` also has a `!shift` guard the keymap's own `Chord::hit` deliberately does not have |

Two invariant breaks:

- `Action::Interrupt` is never dispatched through the keymap; `Esc` is hardcoded
  (`editor.rs:329`, `keys.rs:157`). Rebinding `[keys] interrupt` changes the footer, the `?`
  panel, the palette column and `/keys` — and nothing else. This is the exact failure
  `keymap.rs:12-18` was written to prevent.
- `ctrl+q` and `ctrl+c` run before the overlay dispatch with no `overlay.is_none()` guard
  (`keys.rs:36-39`, `:65-68`); `ctrl+q` inside the credential editor replaces it with the
  quit dialog and the typed key is gone. Every other global chord carries the guard.

### 2.5 Help, footer, which-key *(live)*

- The `?` panel's key column is `{key:<15}` (`view.rs:3568`), so
  "ctrl+w / ctrl+k / ctrl+u" renders as `ctrl+ukill word…`.
- `Action::group()` defines five groups (`keymap.rs:370-393`); the panel uses a literal
  "SESSION" heading and never shows "getting started" or "leader". Fifteen of seventeen
  leader verbs appear only in the two-second which-key overlay and in `/keys`.
- The which-key overlay is placed bottom-left (`view.rs:3470-3476`) and draws over the
  composer's frame.
- The help footer and the settings header print the raw Erlang node name
  (`nonode@nohost`); so do the Dashboard, the session picker rows, the session cards
  (`IDLE · native · nohost`) and the right-hand context rail. The Upgrade tab's pane title
  carries a raw JSON-RPC code: `[unavailable (-32004): no signing node is configured…`.
- The approval modal's hint names `enter`, `tab`/`r`, `ctrl+o`, `esc` and never how to
  move between answers; digits work only under screen-reader mode (`overlays.rs:872-878`).
- The home screen shows `Folder: <config default>` rather than the directory `ouro` was
  started in when `[defaults] workspace` is set *(live)*; the README says "open it from the
  project you want to work on".

### 2.6 Settings *(live)*

Three sections (`F1 Connections`, `F2 Defaults`, `F3 Runtime`) — a sensible split and it
matches the web's first, second and fourth sections. Gaps: the Connections list mixes
"OpenAI / Anthropic / xAI" with lowercase "alibaba / alibaba cn"; per-session runtime
settings (`/model`, `/plan`, `/sandbox`, `/effort`, `/auto-approve`) are slash-only and
absent from the overlay; and eight `config.toml` sections (`[terminal]`, `[statusline]`,
`[notifications]`, `[keys]`, `[theme]`, `[accessibility]`, `[budget]`, `[location]`) have
no UI at all (`config.rs:91-112`).

## 3. Web UI

### 3.1 Navigation and hierarchy *(live)*

- **No global nav.** The topbar (wordmark, machines, tokens, connection pill, bell, theme,
  Settings, Audit, New session) exists only on the deck (`deck_live.ex:1491-1532`). `/new`
  and `/settings` carry a "← Sessions" link and a theme toggle; `/status` and `/audit`
  carry a breadcrumb. Three header treatments, none of which reaches the other spokes.
- **`/status` is orphaned.** No template links to it (`grep href="/status"` is empty), its
  title is "Advanced · Runtime", and it duplicates half of Settings → "Runtime & security".
- **The connection pill and the bell exist only on the deck**, so a person filling in
  `/new` or reading `/audit` gets no signal that the socket dropped or that a session
  started waiting.
- The empty deck draws three empty rail groups ("NEEDS YOU / nothing here", "AT WORK /
  nothing here", "SETTLED / nothing here") under a marketing eyebrow ("A little direction.
  A lot of possibility.") on a console that otherwise refuses to say anything unmeasured.
- Type hierarchy is inconsistent across pages: EB Garamond display headings on `/settings`,
  `/status`, `/audit` and the deck hero; a sans heading for the same rank on `/new`;
  small-caps serif card titles on `/status`/`/audit` only. Google Fonts are loaded from the
  network for a loopback operator console (`layouts.ex:102-106`).

### 3.2 Deck regressions

- **Rail activity line is dead code.** `activity/1` matches `when is_list(cells)`
  (`deck_live.ex:2365`) but `:cells` is assigned `%{}` at mount and `Map.new(...)` on every
  redraw (`:153`, `:654`, `:1302-1306`, `:1353`). Every row falls back to
  `provider · machine`, so nothing distinguishes a session doing work from one sitting still.
- **Vitals and auto-approve are behind a disclosure on every viewport.** `vitals/1` renders
  inside `<details class="ouro-vitals-mobile">` under the composer (`deck_live.ex:2053-2057`),
  never as the third column the moduledoc (`:5-8`) and seven `.ouro-columns > .ouro-vitals`
  rules (`app.css:461`, `:1789`, `:1801`, `:2562`, `:2607`, `:3050`, `:3799`) expect. Model,
  context meter, cost, file access, machine, workspace and the **auto-approve toggle** are
  one click behind "Session details" *(live)*.
- Session verbs are scattered over four disclosure patterns: Rename/End/Delete in a
  hover-revealed `⋯` row menu; Interrupt/Retry in the composer; sandbox/thinking behind
  "Change"; auto-approve inside "Session details".
- The session id appears nowhere but the URL, although `rail.ex:165-166` says it is in
  "session details".

### 3.3 Composer *(live)*

Supports: Enter / Shift+Enter, per-session drafts, queue while running, interrupt, retry,
per-session sandbox and thinking pickers. Does not support: slash commands (`/` types a
slash), `@` files, images, steer, `!cmd`, per-turn effort, model change, copy, export.
There is no on-screen hint for any key.

### 3.4 Keyboard

Three handlers in `app.js`: `/` focuses the rail search (`:237-249`), `Escape` closes row
menus and dialogs (`:488-494`, `:616-622`), `Enter` submits the composer (`:411-427`).
`docs/WEB.md:351` claims ⌘. and ⌘N; neither exists. The only visible hint is the `<kbd>/</kbd>`
in the search box.

### 3.5 Settings and new session *(live)*

`/settings` has an anchor nav with four sections — AI connections, Session defaults,
Providers & models, Runtime & security — and this is the best-categorised surface on either
client. Two issues: "Session defaults" reconciles the model with `NewSession.model_field/1`
(`settings_live.ex:363`, `:378`) while `/new` uses `/2`, so a remembered model outside the
catalogue snapshot is reset to the runtime default when any other field is touched; and the
model picker is a 113-row `<select size=8>` inside "Advanced settings" on `/new`, while
the composer offers no way to change the model once the session exists.

`/audit` shows the raw atom `Audit operation failed: :audit_disabled` as its first line
when auditing is off *(live)*; `/status` and `/settings` show `nonode@nohost`.

Mobile behaviour is deliberate and good (rail and transcript become exclusive panes,
sticky composer, larger targets); the stylesheet declares the same breakpoints three times
with later blocks overriding earlier ones (`app.css:1782`/`:3741`; `:1837`/`:3721`/`:3847`).

## 5. Proposals

### 5.1 One command catalogue

The web already ports the transcript projection from the TUI and pins both to one corpus.
Do the same for verbs: a single catalogue (id, label, group, slash spelling, key action,
gate) that the TUI's `Command::ALL` and a web command palette both read. Gating stays where
it is (`palette_commands` on one side, `Call.available?/2` on the other) but the *list* is
one list, so a verb added on one surface exists on both or is explicitly marked TUI-only
(scrollback, `$EDITOR`) or web-only (audit, browse).

### 5.2 Categorisation, both surfaces

Replace "Coding / Runtime & distribution" with five groups, and use the same five as the
`?` panel's headings and the web palette's sections:

| Group | Verbs |
|---|---|
| **Session** | new, options, switch, rename, end/remove, fork, handoff, writable |
| **Turn** | send/queue, steer, interrupt, retry, effort, model, plan, sandbox, auto-approve, approval |
| **Conversation** | backtrack, rewind, compact, context, details, changed files, raw, copy, copy source, export, scrollback, `$EDITOR` view, verbose, plan panel |
| **Runtime** | dashboard/nodes, logs, upgrades, MCP, capabilities (list/preview/admit), connect |
| **Client** | settings, theme, keys, help, quit |

Settings keep the web's four sections on both surfaces (the TUI's three map onto them);
add a fifth, **Client**, to the TUI for the eight `config.toml` sections that have no UI.

### 5.3 TUI key map

Keep the leader and everything that already matches opencode. Change:

| Action | Now | Proposed | Why |
|---|---|---|---|
| exit | `ctrl+q`; `ctrl+d` on empty | `ctrl+c` twice anywhere (keep `ctrl+q` as alias, guarded by `overlay.is_none()`) | opencode / Claude Code / Codex all exit on `ctrl+c`; `ctrl+q` is flow control on `ixon` terminals |
| editor on draft | `ctrl+g` | `<leader>e` only; free `ctrl+g` | readline abort; opencode `<leader>e` |
| end / remove session | `<leader>x` | `<leader>k` (confirm dialog kept) | opencode `<leader>x` is export |
| export | `/export` | `<leader>x` | opencode |
| compact / model / theme | slash only | `<leader>c` / `<leader>m` / `<leader>t` | opencode |
| backtrack | `esc esc` | keep, add `<leader>g` | opencode timeline; `esc esc` breaks zsh vi-mode habits, which `keymap.rs` itself cites |
| steer | `<leader>s` | `alt+enter` and `/steer` only; `<leader>s` → dashboard (status) | opencode `<leader>s` |
| tabs | `1-7`, `Tab` (home only) | `<leader>1`–`<leader>4`, and draw a tab strip in the header | reachable with a session open; visible |
| rail toggle | — | `<leader>b` | opencode |
| rename | — | `ctrl+r` and `/rename` | opencode; web parity |
| suspend | — | `ctrl+z` | opencode |
| settings | `,` on empty prompt | `<leader>,` and `/settings` only | a message can start with a comma |
| help | `?` on empty prompt | keep `?`, drop the `!shift` guard | Claude Code parity; the keymap already masks SHIFT |
| completion | Tab accepts, Enter submits | Enter accepts the highlighted row when a menu is open; unknown `/verb` is refused with a notice, never sent | every neighbour; stops "/ke" starting a session |
| interrupt | hardcoded `esc` | dispatch through `Action::Interrupt` | the map is the authority |
| `ctrl+d` | quit / delete | delete-forward only (rebindable) | one meaning |

Also: bind `home`/`end` in the transcript to first/last message when the draft is empty;
sort the palette by group; truncate labels before the shortcut column; add
`/diff`, `/raw`, `/keymap`, `/usage` to the completion table; show the answer-movement keys
in the approval modal; keep `Space` peek inside the picker and make `Enter` open.

### 5.4 Web

1. One topbar on every page, with Status linked and the connection pill and bell on all of
   them. Breadcrumb under it, not instead of it.
2. Fix `activity/1` (`deck_live.ex:2365`) — pattern-match the map, or list the values.
3. Move auto-approve and the file-access posture into the composer's status row (where the
   TUI's footer has them); keep the rest of the vitals in a real third column on wide
   viewports or delete the dead CSS.
4. A `ctrl+k` / `⌘k` command palette reading the shared catalogue, an `esc` that
   interrupts when the composer is focused and a turn is running, `?` for a shortcut sheet,
   `n` for new session when focus is not editable, `[`/`]` to move between rail rows. Show
   the keys as `<kbd>` hints the way the search box does.
5. Close the served-but-unexposed gaps in this order: copy message, steer, model change
   mid-session, event details (`interactive.event_detail`), export, fork / rewind /
   compact / handoff / context, `!cmd`, MCP list, logs, plan-mode toggle.
6. Translate atoms and node names before they reach a template: `:audit_disabled`,
   `nonode@nohost`, `-32004` should read as sentences on both surfaces.

### 5.5 Docs

`docs/TUI.md` should be corrected where §2.1 and §2.4 show it wrong (`1-7`, `Ctrl-E`,
`i`/`s`/`a`, `Esc` with a draft, peek), and `docs/WEB.md:351` should drop ⌘. and ⌘N.

## Status, 2026-09-15 (ui-parity branch)

The findings above are a record and are not edited. This section says what the
`ui-parity` branch did with each of them, and what it deliberately did not. The TUI rows
were reproduced against the code on this branch while writing
[docs/TUI.md](../TUI.md) §3.4; the web rows are recorded from their own slices' acceptance
and were **not** re-verified by this pass — `docs/WEB.md` is rewritten in T3b, after W3.

### Resolved

| Finding | Slice |
|---|---|
| §2.1 `1`–`7` documented as tabs; `5`–`7` swallowed; no tab bar drawn | T1.6 (digits bounded by `Tab::ALL`), T2.4 (header strip), T1.5 (`ctrl+x 1`–`4`) |
| §2.1 `i`, `s`, `a`, `,` dead in the list layer | T1.6 — the arms are removed, not documented |
| §2.1 `q` in the list layer bypassed `[keys] quit` | T1.6 — silenced when `quit` is `off` |
| §2.1 `Esc` with text did nothing although the docs said it kept the draft | T1.7 — the draft goes to prompt history, one notice names `up` |
| §2.1 `Space` peek replaced the picker; its hint named the opposite key | T2.6 — `Peek { from_picker }`, `Enter` opens, `Esc` returns to the row |
| §2.2 two palette groups, each heading drawn three times, no sort | T2.1 — five groups, sorted, each heading once |
