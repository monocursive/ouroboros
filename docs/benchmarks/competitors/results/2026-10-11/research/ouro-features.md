# Ouroboros Jail (`ouro-jail`) — Feature Summary

**Product:** standalone Linux sandbox for AI agents and CLI tools; wraps an operator-supplied command, restricts file access, network destinations and runtime, and produces a receipt per attempt. Developer preview **0.1.0-rc.1** (signed Linux x86_64 + ARM64 packages). *(README.md)*

## 1. Platform support matrix

| Platform | Status | Source |
|---|---|---|
| Linux x86_64 | Execution supported. Reference host: Ubuntu 26.04.1, kernel 7.0-series, bubblewrap 0.11.1; host must run its own kernel (VM ok; containers without user-namespace/cgroup delegation are ineligible) | README.md; docs/specs/jail-v1.md §3.2; docs/specs/jail-v1/operating.md |
| Linux arm64 | Execution supported; native checks on Raspberry Pi 4 / Debian 13 recorded. Tested Pi lacks memory cgroups and Landlock → default `build` profile unavailable there; proxy enabled via a provisioned exact-kernel Unix diagnostics module | README.md; docs/guide.md; docs/specs/jail-v1/operating.md |
| Other Linux arches / musl (Alpine) | Refuse execution with 125 (`unsupported_architecture`); binaries require glibc ≥ 2.39 | docs/specs/jail-v1/operating.md; docs/guide.md |
| Stock Ubuntu 24.04 | Containment refused — distro bubblewrap 0.9.0 < required 0.10.0 (`bwrap_too_old`) | docs/guide.md; docs/specs/jail-v1/operating.md |
| Native macOS build | Inspection only: `version`, `explain`, `doctor` work; `run` refuses with exit 125 before exec. Native macOS execution (Seatbelt/ES lane, J11) has an open design gate — Endpoint Security entitlement pending and process-tree cleanup unproved | README.md; docs/specs/jail-v1.md §3.2; docs/specs/jail-v1/operating.md; docs/specs/jail-v2.md §8 |
| macOS VM preview (`ouro-vm` 0.1.0-preview.1) | Signed + notarized DMG for **Apple Silicon, macOS 27+** (tested macOS 27.0.1); runs **offline Linux ARM64 commands in a disposable VM**. Needs ~8 GiB free APFS, 2 vCPUs + 2 GiB RAM per attempt; ~22 s startup/attempt. Intel Macs and nested VM unsupported. ## 2. Isolation mechanisms

- **Namespaces:** every contained profile runs in **one bubblewrap layer** with its own **user, mount, PID, network, IPC and UTS namespaces**, new session, parent-death chain, and a closed filesystem view assembled from declared roots. *(README.md; docs/specs/jail-v1.md §9.2; docs/specs/jail-v1/operating.md "Profiles")*
- **Seccomp:** versioned, architecture-aware filter recorded by digest in the receipt; `no_new_privs` set and **no capabilities** before any user instruction runs. Baseline denies host tracing/inspection (`ptrace`, `process_vm_*`, `bpf`, `perf_event_open`), kernel replacement/module interfaces, keyring grants, terminal injection, the clock-adjustment family (`adjtimex`, `clock_settime`, `clock_adjtime`), `quotactl`, `settimeofday`/xattrat family, and **`io_uring_*` (EPERM) in every contained profile**. `clone3` → ENOSYS in `tool`/`build` and in the observer filter; `clone` with `CLONE_UNTRACED` refused. Sockets only in AF_UNIX/AF_INET/AF_INET6 (others EAFNOSUPPORT). No arbitrary user seccomp expressions. *(README.md; docs/specs/jail-v1.md §9.2; docs/specs/jail-v2.md §3.4–3.5; docs/specs/jail-v1/operating.md "Named limits")*
- **`agent` inner-sandbox carve-out:** its filter permits an inner vendor sandbox's `no_new_privs`, own seccomp filters and **Landlock**; nested user namespaces are an optional measured host capability (unavailable on stock Ubuntu ≥24.04 — reported, not fatal). Jail never disables or rewrites an inner sandbox. *(docs/specs/jail-v1.md §9.2; docs/specs/jail-v1/operating.md "Profiles", "Named limits")*
- **AF_UNIX mediation (agent):** seccomp user-notification mediation of `connect` — host Unix peers unreachable except the authorized proxy (admitted only for the bridge's pinned identity); same-attempt IPC works. Datagram/raw AF_UNIX refused at socket creation. *(docs/specs/jail-v1.md §10; docs/specs/jail-v1/operating.md "Profiles")*
- **Observation:** a **ptrace observer in the supervisor** attaches before target release and follows the whole tree (closed set, §6 below). *(docs/specs/jail-v1.md §5.2, §11; README.md)*
- **Hardening details:** supervisor and proxy bridge make themselves non-dumpable; resolv.conf sanitized per attempt; execution-leaf (cgroup) protection during bubblewrap startup; binary/backend isolation guards refuse child-writable roots over the jail or `bwrap` binary; backend exec'd via pinned descriptor (`fexecve`). *(docs/specs/jail-v1/operating.md "Named limits"; docs/specs/jail-v2.md §3.2–3.3; docs/specs/jail-v1.md §9.1)*
- **No host configuration:** no sysctl, AppArmor profile, file capability, setuid helper or sudo required or changed; euid 0 and a set-uid supervisor refuse. Effective UID 0 refuses. *(docs/specs/jail-v1/operating.md "Install")*

## 3. Filesystem policy model

**Profiles** (starting policies; *(README.md; docs/guide.md; docs/specs/jail-v1/operating.md "Profiles")*):

| Profile | Filesystem | Network | Default limits |
|---|---|---|---|
| `tool` | workspace + scratch writable; system roots read-only; existing `.git` and `.ouroboros` trees beneath writable roots protected from writes | none | wall 30 m (required), pids 256 (preferred) |
| `agent` | workspace, scratch and temporary agent/vendor state (`/run/ouro/state`) writable; system roots read-only; git metadata writable **except `.git/hooks` and `.git/config`** (hook-planting protection); a `.git` created by a fresh clone inside the run is not protected | proxied destinations require grants | wall 2 h, pids 512 (preferred) |
| `build` | declared inputs read-only, scratch writable; output paths granted explicitly | none | wall 1 h, pids 512 (preferred), **explicit `mem` required** |
| `none` | host view unchanged (uncontained) | host's | wall 2 h; receipts always `child_protection: unprotected` |

- **Grants:** `--ro PATH` (read visibility), `--rw PATH` (writable), `--deny-read PATH` (exclusion); grants checked against resolved objects, by filesystem type/topology not path spelling. *(docs/guide.md; docs/specs/jail-v1/operating.md "Commands", "Profiles")*
- **Closed view:** only declared system roots are bound (`/usr`, `/bin`, `/lib*`, specific `/etc` files); private child `/proc` and minimal `/dev`. Grants resolving onto host `/proc`, `/sys`, cgroupfs, devtmpfs, or `/run` tmpfs — or ancestors thereof — refuse with `policy_widening`; `--ro /` refuses. Sole exception: explicit `--rw` grant of an allowlisted **NVIDIA device node** (GPU passthrough, `gpu_passthrough` doctor row). *(docs/specs/jail-v1.md §9.1; docs/specs/jail-v1/operating.md "Profiles")*
- **Git protection scope (`tool`):** `existing_and_root` — `.git`/`.ouroboros` segments existing at launch plus root-level literals (also when absent); newly created deep segments during the run are not covered; `all_descendants` refuses on Linux. Scan bounds: 100,000 entries, depth 128. *(docs/specs/jail-v1.md §9.1; docs/specs/jail-v1/operating.md "Named limits")*
- **Narrowing-only config:** project `ouro.toml` at the workspace root can only narrow (never select a profile, add grants, raise/remove limits, weaken coverage/evidence, add credentials or select `none`); operator `--profile FILE` extends a built-in contained profile and may only narrow or add finite limits. *(README.md; docs/specs/jail-v1/operating.md "Profiles")*
- **Named limit:** the workspace is not a repository boundary — shared inodes and Git alternates reach what they point to. *(docs/specs/jail-v1/operating.md "Named limits")*
- **macOS VM variant:** inputs are copied into a private guest disk; `tool` and `build` allow writes to the disposable workspace copy; protected system paths read-only. *(docs/guide.md "macOS VM preview")*

## 4. Network policy

- **Model:** `tool` and `build` have **no network at all**. `agent` reaches the network only through an **outside proxy** exposed via an attempt-specific Unix socket and an in-namespace loopback bridge at `127.0.0.1:3128` (HTTP CONNECT) plus a **SOCKS5** listener at `127.0.0.1:3129` (`socks5h`; bridge resolves, child never does). Proxy env vars (`HTTP_PROXY`/`HTTPS_PROXY`/`ALL_PROXY`=…3128 / `socks5h://…:3129`) set for the child. **UDP is unsupported** (SOCKS5 `UDP ASSOCIATE` → REP=0x07, `BIND` → 0x02). No TLS interception in the base lane. *(README.md; docs/guide.md; docs/specs/jail-v1.md §10; docs/specs/jail-v2.md §6.1)*
- **Destination grants:** `--allow-host HOST[:PORT]` (and launch-profile `network.allow`). **Omitted port means 443 only** (v2 deliberate breaking change; port 80 etc. need explicit `host:port`). Name-based allowlisting with pinned IDNA/normalization; `*.example.com` matches one-or-more subdomain labels; IPv4/IPv6 literals are explicit address grants. Forbidden-address table (private, loopback, link-local, multicast, metadata/service prefixes) rejects resolved addresses unless explicitly granted; mixed allowed/forbidden DNS answers rejected; DNS resolves on the host, not in the jail. *(docs/guide.md; docs/specs/jail-v2.md §3.1; docs/specs/jail-v1.md §10)*
- **Origin binding:** the bridge buffers the client's first flight (≤8 KiB / 5 s) and requires TLS ClientHello **SNI** (or plaintext HTTP `Host`) to match the authorized target; mismatches close the tunnel (`origin_mismatch` / `origin_unverified` / `origin_timeout`). Documented residual: after the first flight the tunnel is opaque (CDN co-tenancy); evidence names the actual verification (`http_host`, `tls_sni`, `explicit_ip`, …). *(docs/specs/jail-v2.md §3.1, §6.2)*
- **Credential vaulting (optional, `mode = "vault"`):** no secret bytes staged in child files or environment — child gets placeholder `OURO_VAULT_<ID>`; plaintext-HTTP lane substitutes into `Authorization` headers at the bridge (explicit opt-in); TLS lane uses a per-attempt CA (key only in supervisor memory), substitutes for exact authorized origins and re-originates TLS upstream; receipts record `never_staged: true`, no digest. Staged modes also exist: `copy_rw` / `bind_ro` into vendor state at `/run/ouro/state` (16 MiB copy budget, single-link sources, vendor state removed at settlement). Residual, documented: an authorized upstream can still return a vaulted secret in a response. *(README.md; docs/guide.md; docs/specs/jail-v2.md §6.3; docs/specs/jail-v1/operating.md "Launch profiles and credentials")*
- **Budgets:** 128 active connections, 32 KiB request headers, 10 s DNS/connect/header deadlines, 1 MiB bounded relay buffers; fail-closed on proxy/bridge death; no paths/headers/tokens/bodies logged. *(docs/specs/jail-v1.md §10)*
- **Command deny-rules (opt-in, J10):** `[jail.commands] deny`/`forbid` positional-glob rules enforced at the exec gate (`deny` → EPERM + `command_denied` event; `forbid` → tree stop `command_forbidden`); explicitly an accident filter, not a boundary. *(docs/specs/jail-v2.md §7.2; docs/guide.md "Understand the boundary")*

## 5. Resource ceilings

- **`--limit` keys:** `wall` (ms/s/m/h), `pids`, `mem` (bytes/KiB/MiB/GiB), `swap` (same grammar; `swap=0` disables swap; never implied by `mem`), `storage`, `inodes`, `cpu` (percent of one core — bandwidth ceiling, not CPU-seconds). **Every explicit limit is required**: if unenforceable, the run refuses. *(docs/specs/jail-v1.md §6.4; docs/specs/jail-v1/operating.md "Commands"; docs/guide.md)*
- **cgroup v2 delegation:** `pids.max`, `memory.max`, `memory.swap.max` and `cpu.max` are written to a per-attempt **execution leaf** in the cgroup v2 subtree systemd delegates to the user manager; `run`/`doctor` enter a transient user scope (via `busctl`) where the account **lingers** (`loginctl enable-linger`). Without lingering there is no execution leaf: `none` and any explicit pids/mem/swap/cpu limit refuse with 125, and preferred pids ceilings are recorded unapplied. *(docs/specs/jail-v1.md §9.3, §6.4; docs/specs/jail-v1/operating.md "Lingering and the scope step")*
- **Wall deadlines** enforced by the supervisor on `CLOCK_BOOTTIME` (suspend counts). A receipt becomes `settled` only after the process tree is verified dead. *(docs/specs/jail-v1.md §6.4; README.md)*
- **Storage/inode ceilings** require operator-provisioned bounded tmpfs or ext4/XFS **user hard quotas** (kernel `Q_GETQUOTA` verified before release; soft limits/foreign files/idmapped mounts/XFS realtime refuse); under storage ceilings `/dev/shm` is read-only and new hard links return EPERM; `hit=null` means saturation unknown. Project quotas and auto-provisioning unimplemented. *(docs/guide.md; docs/specs/jail-v1.md §6.4)*

## 6. Observation and receipts

- **Artifacts:** each attempt saves a `jail.json` receipt (schema `ouro.jail.receipt/1`), the resolved policy, and a `trace.ndjson` journal under `~/.local/share/ouro/attempts/<id>/` (`OURO_DATA_DIR` relocatable); `--receipt PATH` adds a copy outside child-writable grants. *(README.md; docs/guide.md; docs/specs/jail-v1/operating.md "Reading a receipt")*
- **Receipt fields:** `phase` (`prepared`/`enforced`/`settled`/`refused`), `outcome` (`kind` exited/signaled/exec_error/refused/unknown, `code`, `signal`, `cause` e.g. `wall_expiry`/`evidence_loss`, `error`), `containment` + `child_protection`, `applied` (actual mounts, network mode, filter digests, limits with `hit`), `lifetime` (`tree_empty`, `verification_scope`, `integrity`), `observer`/`coverage` per class (**exec, fs.write, fs.deny, net, proxy.net, limits** — each `status`/`observed_count`/`gaps`), `errors`, `state_cleanup`, `credentials`. Missing evidence stays explicit; a zero count claims only "no observed events under active coverage". *(README.md; docs/guide.md; docs/specs/jail-v1/operating.md "Reading a receipt")*
- **Trace:** NDJSON `ouro.event/1` events (observer audit results, proxy results, wrapper notes); `tail`, `tail --follow`, `tail --attempt ID --json`; complete only if the last line is the `jail.receipt` note. *(README.md; docs/guide.md; docs/specs/jail-v2.md §7.1; docs/specs/jail-v1/operating.md)*
- **Strict evidence:** default; loss of required evidence stops the run (exit 1) — `best-effort` continues with degraded, gap-named coverage. Observation is on by default and covers a **closed set** (`linux-closed-v1`): exec/exit, file creation, open-for-mutation, truncation by path, rename, unlink, directory-entry creation, `connect`, and their EACCES/EPERM denials. Reads, writes, mmap, payloads and read denials are **not** observed. *(README.md; docs/specs/jail-v1/operating.md "Reading a receipt", "Named limits")*
- **Cost:** each observed call ≈ two ptrace stops (~22 µs each); startup +91–120 ms median; observation multiplies file-heavy work ~5×. *(docs/specs/jail-v1/operating.md "Observation cost"; README.md "Performance and validation": 7.4% improvement record, p95 +126.7 ms startup, observation-on +319.6% file-work over off)*
- **Exit codes:** child's code; 128+signal; 125 refusal before exec; 1 post-start tool/evidence failure (e.g. `exec_unconfirmed` under `--observe off`); 2 usage. *(docs/specs/jail-v1/operating.md "Exit codes"; docs/guide.md)*
- **Supporting commands:** `explain` (resolved policy + digest, no probing), `doctor` (probe-based host manifest `ouro.jail.doctor/1`, 5 s probes, ready/125), `gc` (crash reconciliation, identity-checked), `version` (build provenance, frozen schemas, closed set), `run --label-only`, and a managed-gate protocol (`--gate-fd`/`--control-fd`, digest-matched release, at-most-once execution). *(docs/specs/jail-v1/operating.md; docs/specs/jail-v1.md §14, §8.2)*

## 7. Permission learning (`learn`)

- `ouro-jail learn` runs one ordinary contained run (observation forced **on**, strict evidence, never `none`) and writes a proposal derived from that run's evidence: **exact read-only paths** (only absolute, untruncated, host-verified objects; never the parent tree; pseudo-filesystem paths stay unresolved) and **denied network destinations** (only `host_not_allowed` proxy denials). **Denied writes are reported but never proposed as grants.** *(docs/guide.md "Learn missing permissions"; README.md; docs/specs/jail-v2.md §5.1)*
- Output is a `ouro.jail.learned-policy/1` document with mandatory provenance (attempt id, receipt digest, per-class counts, coverage summary, revision), written 0600; `--adopt` prints the exact config change and requires **interactive TTY confirmation**, appending atomically to `config.toml` under a marker comment. A proposal describes one observed run, not the program's full needs; nothing adopted automatically. *(docs/specs/jail-v2.md §5.1–5.3; docs/guide.md)*

## 8. Agent launch profiles

- **Fourteen embedded starter profiles:** `opencode`, `claude`, `codex`, `cursor`, `aider`, `goose`, `gemini`, `amp`, `cline`, `copilot`, `kilo`, `auggie`, `droid`, `pi` (v2 spec additionally defines data-only toolchain fragments `node`, `python`, `go`, `rust`, `java`, `ruby`, `scm`, `containers` composable via `bundles`). *(docs/specs/jail-v1/agent-compatibility.md; README.md; docs/specs/jail-v2.md §4.4)*
- **What they set:** starter file grants, environment mappings into vendor state, credential inputs, allowed hosts, and a default contained profile. They **never supply argv** and cannot select `none`; profiles do not install agents, and normal login state is not auto-exposed. Embedded via `include_str!`; an operator file at `<config>/launch/NAME.toml` shadows the bundled one. `--launch NAME` + you supply the executable/args; `doctor --launch` checks profile inputs without printing values. *(docs/guide.md "Run an existing agent"; docs/specs/jail-v1/operating.md "Launch profiles and credentials"; docs/specs/jail-v2.md §4.4)*
- **Status:** all profiles remain `experimental` until a compatibility row covers the exact agent version + jail build. Recorded live runs: **OpenCode 1.18.32** (multiple passing rows on Ubuntu x86_64 and Raspberry Pi, incl. credentialed GLM run and learn fixture) and **Gemini CLI 0.63.0** (version-flag npm-shim row). Repeated real-agent qualification remains experimental. *(README.md; docs/specs/jail-v1/agent-compatibility.md; docs/guide.md)*

## 9. Ledger (`ouro-ledger`)

- First slice available in source: reserves one attempt, records **durable admission before releasing the jail's execution gate**, stores source events and settlement; commands `runs`, `show`, `verify`, `settle-orphans`; operator `append` records independent assertions without changing launch state; `tail -f RUN --json` follows canonical records with resumable byte positions and explicit coverage/protection labels; **output capture opt-in and bounded** (default 1 MiB/stream); NDJSON export preserves exact canonical record bytes. *(README.md "Local ledger work"; docs/specs/ledger-v1.md)*
- Full ledger adds bounded cross-run discovery/comparisons, **signed portable bundles** (`bundle`/`bundle-keygen`/`verify-bundle`, §8.4–8.5), best-effort writer-outage recovery, hold/release/gc retention (§8). **Linux owns execution; macOS supports local store inspection.** The jail works independently without the ledger; the ledger and fleet are **not included** in the signed release packages. *(README.md; docs/specs/ledger-v1.md; docs/guide.md)*

## 10. Install footprint

- **Single Rust binary** installed to `~/.local/bin` (no daemon, no sudo, no privileged service, no Rust toolchain needed for install); installer needs only Bash, curl, tar and sha256sum/shasum. *(README.md "Install and run"; docs/guide.md; docs/specs/jail-v1/operating.md "Install")*
- **Runtime dependency:** the distribution's **bubblewrap** package, **≥ 0.10.0 required** (every contained run renders `--bind-fd`/`--ro-bind-fd`; reference host 0.11.1); resolved once per process from the first absolute `PATH` entry; `doctor` records its path, SHA-256 and version; glibc ≥ 2.39. *(README.md; docs/guide.md; docs/specs/jail-v1/operating.md "Install")*
- **Installer integrity:** Bash installer embeds SHA-256 hashes for both Linux archives and the Mac DMG and verifies before extracting/executing; supports `--from-dir` offline install, `--bin-dir`, pinned `--version`, `--allow-downgrade`. *(README.md; docs/guide.md "Install the developer preview", "Verify a supplied package")*
- **`ouro-jail` binary size: UNKNOWN** — no binary/tarball size figure is documented in the repo docs searched. The macOS VM package size **is** documented: DMG 536,341,282 bytes (511.5 MiB), installing runtime + guest image under `~/.local/share/ouro-vm/0.1.0-preview.1`. *(docs/releases/ouro-vm-0.1.0-preview.1.md "Package identity")*
